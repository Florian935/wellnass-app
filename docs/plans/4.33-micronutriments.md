# US 4.33 — Micronutriments — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Enrichir la base d'aliments et le journal d'un **socle de 10 micronutriments** (cholestérol, sodium, magnésium, potassium, calcium, fer, vitamines C/D/B9/B12), stockés dans une **colonne JSON `micronutrients`**, **figés (snapshot)** dans le journal, affichés **uniquement quand la donnée existe**. Zéro régression sur l'existant.

**Architecture:** La **logique pure** (schéma `Micronutrients`, `scaleMicronutrients`, `sumMicronutrients`, `saltFromSodiumMg`) vit dans [`packages/shared/src/food.ts`](../../packages/shared/src/food.ts) (+ tests Vitest), à côté de `scaleNutrition`/`sumNutrients` existants. Le JSON suit le patron **`portions`** déjà en place (colonne `text` PowerSync / `jsonb` Postgres, sérialisée par le repo). Les repos ([`food-repository`](../../apps/mobile/src/data/repositories/food-repository.ts), [`journal-repository`](../../apps/mobile/src/data/repositories/journal-repository.ts)) lisent/écrivent le JSON. Le mapping OFF ([`lib/openfoodfacts.ts`](../../apps/mobile/src/lib/openfoodfacts.ts)) est étendu avec **normalisation d'unité**. L'UI ajoute une section repliable « Valeurs détaillées ».

**Tech Stack:** identique — `@wellness/shared` (TS + Vitest), `apps/mobile` (Expo SDK 57, PowerSync `useQuery`, i18next), migrations Supabase. **Aucune nouvelle dépendance.**

**Spec :** [4.33-micronutriments.md](../specs/functional/us/4.33-micronutriments.md) · **Patterns à copier :** `portions` (JSON déjà géré de bout en bout : schéma → colonne → repo → UI), `scaleNutrition`/`sumNutrients`, mapping `mapProduct` OFF, section quantité du food-picker.

**Branche :** `feature/4.33-micronutriments`, depuis `dev` (déjà créée ; spec à committer).

**Hors périmètre (rappel spec §8) :** agrégat micros du jour, objectifs/RDA, micros dans recettes/repas types, extension du panel. **Checkpoint 🔴 cloud requis** (migration + re-seed + sync rules).

## Rappels de patron

- **Clés stables, unité dans le nom** (`magnesium_mg`, `vitamin_d_ug`). Jamais renommées. Absence = **clé omise**, jamais `0`.
- **Valeurs `foods` = pour 100 g** ; **valeurs `food_entries` = figées pour la quantité** (snapshot, comme les macros).
- **JSON de bout en bout comme `portions`** : `column.text` (PowerSync) / `jsonb` default `'{}'` (Postgres) ; `JSON.parse`/`stringify` dans le repo ; validation Zod au passage.
- **Rétrocompatibilité absolue** : colonne à défaut `'{}'`, tout aliment/entrée existant reste valide. Lecture tolérante (clés inconnues ignorées), écriture stricte (panel connu).
- **Réactivité** : lecture via `useQuery` PowerSync existant ; aucun nouvel état.
- **i18n FR + EN miroir** : 10 libellés + « Valeurs détaillées » + unités.

## Panel (clés canoniques)

`cholesterol_mg`, `sodium_mg`, `magnesium_mg`, `potassium_mg`, `calcium_mg`, `iron_mg`, `vitamin_c_mg`, `vitamin_d_ug`, `vitamin_b9_ug`, `vitamin_b12_ug`. Sel = dérivé `sodium_mg × 2.5` (non stocké).

## Points de vigilance

- **Unités OFF hétérogènes** (g vs mg vs µg selon produit/champ) : normaliser strictement, sinon valeurs 1000× fausses. Tester.
- **Ne jamais afficher `0` par défaut** ni bloquer un aliment sans micros.
- **Snapshot** : l'édition de quantité doit recalculer le snapshot micros (sinon dérive avec les macros).
- **Sync rules** : vérifier si les streams `foods`/`food_entries` énumèrent les colonnes (sinon la nouvelle colonne ne serait pas synchronisée). Checkpoint 🔴.
- **Seed CIQUAL** = gros du travail data et source d'erreurs de saisie → relire les valeurs.
