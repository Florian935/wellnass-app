# Plan d'implémentation — Admin Fondation-1 (scaffold + auth + shell)

> Exécuter avec `superpowers:subagent-driven-development`. Spec validée :
> [docs/specs/functional/us/8.1a-admin-fondation-scaffold-auth.md](../specs/functional/us/8.1a-admin-fondation-scaffold-auth.md).
> Branche : `feature/admin-f1-scaffold-auth`. **100 % client web, aucune migration/cloud.**

**Objectif :** app web `apps/admin` (Vite+React+TS) qui démarre, se connecte via Supabase, et protège ses routes
(shell + placeholder). Roles/RLS = F2 (lot suivant).

**Architecture :** SPA Vite+React ; `supabase-js` (env `VITE_*`, session localStorage) ; `react-router-dom` avec
`RequireAuth` ; contexte `useAuth` (`getSession` + `onAuthStateChange`) ; libellés **FR centralisés** ; réutilise
`@wellness/shared` (type `Database`).

## Maquette
Fournie : `design/admin-f1/admin-f1.html` (login centré + shell : entête « Wellness Admin » + e-mail + Déconnexion,
zone contenu placeholder). Thème clair, accent terracotta `#dd6e40`.

## Contraintes d'intégration monorepo (should-fix de la revue)
- **`react`/`react-dom` épinglés à `19.2.3`** (versions EXACTES, comme `apps/mobile`) → évite un doublon de hoisting.
- **TypeScript `~5.6.3`** (comme `packages/shared`) dans l'admin.
- **`tsconfig.json` admin remplacé** (pas étendu du stub) : `lib: ["DOM","DOM.Iterable","ESNext"]`, `jsx: "react-jsx"`,
  `moduleResolution: "bundler"`, `noEmit: true`, `include: ["src"]`. (Peut étendre `tsconfig.base.json` si compatible.)
- Scripts admin : `dev`, `build`, `preview`, `typecheck`, **`lint`** (nouveau, config web React) — pour que les
  commandes racine `--workspaces --if-present` les incluent. **Pas de modif `ci.yml`.**
- `.gitignore` racine (`.env.*` + `!.env.example`) couvre déjà `apps/admin/.env*` → **aucune modif** ; committer
  `apps/admin/.env.example` uniquement. **Jamais de clé réelle.**
