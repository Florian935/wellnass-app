# US 1.2 — Connexion via Google (OAuth) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommandé) ou
> superpowers:executing-plans. Steps en cases `- [ ]`.
> ⚠️ **Workflow projet** : ne PAS exécuter avant validation des 3 livrables (spec ✅ + plan + maquette).
> ⚠️ **Module natif ajouté → nouveau dev build.** Prérequis externes (Google Cloud + Supabase Auth +
> `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`) = **déploiement contrôlé** (hors code, avant recette). Aucune migration.

**Goal :** créer un compte / se connecter avec Google (natif Android) en complément de l'e-mail/mot de passe.

**Architecture :** Sign-In natif (`@react-native-google-signin/google-signin`) → `idToken` →
`supabase.auth.signInWithIdToken`, branché sur le `auth-store` existant (session via `onAuthStateChange`, même
routing que l'e-mail). Config au démarrage (module side-effect importé dans `_layout.tsx`). Bouton réutilisable +
mention de consentement sur les 2 écrans. Helper **pur testé** de mapping d'erreurs.

**Tech stack :** TypeScript, RN + Expo (SDK 57), `@react-native-google-signin/google-signin`,
`@supabase/supabase-js` (`signInWithIdToken`), Zustand (`auth-store`), i18next, jest-expo.

**Spec :** [docs/specs/functional/us/1.2-connexion-google.md](../specs/functional/us/1.2-connexion-google.md)

## Task 3 : Action `signInWithGoogle()` (auth-store)

**Files:** `apps/mobile/src/stores/auth-store.ts`

- [ ] **Step 1 : implémenter** — ajouter au type `AuthState` et à l'objet du store :
  ```ts
  import { GoogleSignin, statusCodes, isErrorWithCode } from '@react-native-google-signin/google-signin';
  import { mapGoogleSignInError } from '@/lib/google-auth-errors';
  // …
  signInWithGoogle: async (): Promise<AuthResult> => {
    try {
      await GoogleSignin.hasPlayServices();
      const response = await GoogleSignin.signIn();
      const idToken = response.data?.idToken ?? null; // vérifier la forme de retour de la lib (SDK 57)
      if (!idToken) return { error: null }; // annulation / pas de token → no-op
      const { error } = await supabase.auth.signInWithIdToken({ provider: 'google', token: idToken });
      if (error) {
        console.warn('[auth] signInWithIdToken échec:', error.message); // traçabilité (spec §2.5)
        return { error: mapGoogleSignInError(error) }; // clé i18n (contrat Task 3)
      }
      return { error: null };
    } catch (err) {
      if (isErrorWithCode(err) && err.code === statusCodes.SIGN_IN_CANCELLED) {
        return { error: null }; // annulation utilisateur → no-op
      }
      console.warn('[auth] Google Sign-In échec:', err);
      return { error: mapGoogleSignInError(err) };
    }
  },
  ```
  > ⚠️ Détails à trancher/vérifier au code : (1) la **forme de retour** de `GoogleSignin.signIn()` selon la version
  > (`response.data.idToken` vs `response.idToken`) ; (2) `signInWithGoogle` renvoie une **clé i18n** dans `error`
  > (comme les autres actions renvoient déjà un message ?) — **cohérence à vérifier** : `signIn`/`signUp` renvoient
  > `error.message` (texte brut Supabase), pas une clé i18n. **Décision** : `signInWithGoogle` renvoie une **clé
  > i18n** (nos messages maîtrisés) ; l'écran fera `t(result.error)` si la valeur est une clé `auth.google.errors.*`.
  > Documenter ce contrat dans le code (les erreurs Google passent par nos clés, pas par le texte Supabase brut).
- [ ] **Step 2 : vérifier** `npm run typecheck` + `npm run lint`. (I/O natif : pas de test unitaire ; le mapping
  déterministe est couvert par la Task 2 ; le parcours en recette.)
