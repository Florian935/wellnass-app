# Running R4b — Records d'allure + maj auto allure de réf — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Records d'allure personnels (meilleur segment glissant sur 1/5/10 km, semi, marathon) calculés depuis les traces GPS et **persistés**, avec détection à la fin de course (célébration in-app + maj auto de l'allure de référence sur record 5 km) et section « Records » dans l'écran Historique.

**Architecture:** Logique **pure et testée** dans `@wellness/shared` (`pace-records.ts` : cœur math sur tableaux cumul/temps + interpolation + filtre outliers). Table dédiée `running_pace_records` (migration 🔴). Repository dédié `running-record-repository.ts` (lecture réactive + détection idempotente à la fin + backfill). Célébration in-app (RN `Animated`, aucun module natif) sur le résumé de course. Offline-first.

**Tech Stack:** `@wellness/shared` (TS + Vitest), Supabase/PowerSync, `apps/mobile` (Expo Router SDK 57, `useUnits`, i18next). Réutilise `GpsPoint`/`haversineMeters`/`MAX_PLAUSIBLE_SPEED_MS`/`decodeTrack` (running.ts), `upsertRunnerProfile`/`ref5kPaceSPerKm` (running-profile-repository), l'écran `run/summary.tsx` (R1/R2) et `running-history/index.tsx` (R4a).

**Spec :** [5.30-5.31-running-r4b-records.md](../specs/functional/us/5.30-5.31-running-r4b-records.md) (validée). **Patrons :** `run-repository.ts` (`decodeTrack`, `currentUserId`, `useQuery`), `running-profile-repository.ts` (`upsertRunnerProfile` partiel), migration `20260712110000_planned_sessions.sql` (RLS/publication/trigger, convention colonnes), `schema.ts`, `powersync-sync-rules.yaml`.

**Branche :** `feature/running-r4b-records`, depuis `dev` (spec `ab3b6fb`).

> **Décisions verrouillées (rappel spec) :**
> - Records **par course** (`t` = secondes depuis le départ, par course) — jamais à cheval sur deux courses.
> - **Meilleur segment** : temps minimal pour couvrir ≥ D, **interpolation linéaire de `t` au franchissement de D** ; filtre outliers = segment trop rapide contribue **0 m** (point conservé, temps préservé).
> - **Détection idempotente** à la fin (upsert « seulement si strictement plus rapide ») ; **non-re-célébration** garantie par l'upsert renvoyant `[]` (pas de flag persistant).
> - **GPS uniquement** (manuel exclu). **Maj allure réf** uniquement si 5 km battu.
> - Table **`running_pace_records`**, `user_id`, RLS `user_id = auth.uid()`, bucket `user_data`, **index unique partiel `(user_id, distance_key) where deleted_at is null`**.
> - **Aucun module natif** (célébration in-app) → **pas de rebuild** ; seule la migration est un **checkpoint 🔴 cloud**.

    expect(bestSegmentTimeFromSamples([0, 500, 500, 1500], [0, 150, 250, 550], 1000)).toBe(300);
  });

Résultat attendu **300** (vérifié ci-dessus), la zone sans distance réelle étant pénalisée en temps. L'implémenteur garde l'implémentation fournie telle quelle ; le test doit passer sans ajustement.

```ts
import { haversineMeters, MAX_PLAUSIBLE_SPEED_MS, type GpsPoint } from './running';

export type RecordDistanceKey = '1k' | '5k' | '10k' | 'semi' | 'marathon';
export const RUNNING_RECORD_DISTANCES: { key: RecordDistanceKey; meters: number }[] = [
  { key: '1k', meters: 1000 },
  { key: '5k', meters: 5000 },
  { key: '10k', meters: 10000 },
  { key: 'semi', meters: 21097.5 },
  { key: 'marathon', meters: 42195 },
];

/** Distance cumulée le long de la trace (outlier de vitesse → 0 m ajouté, point conservé). */
export function cumulativeDistances(points: ReadonlyArray<GpsPoint>): number[] {
  const cum: number[] = new Array(points.length);
  cum[0] = 0;
  for (let i = 1; i < points.length; i++) {
    const prev = points[i - 1]!, curr = points[i]!;
    const dt = curr.t - prev.t;
    let d = 0;
    if (dt > 0) {
      const dist = haversineMeters(prev, curr);
      if (dist / dt <= MAX_PLAUSIBLE_SPEED_MS) d = dist;
    }
    cum[i] = cum[i - 1]! + d;
  }
  return cum;
}

/**
 * Temps minimal (s) pour couvrir >= `targetDistanceM` sur des échantillons (distance cumulée `cum`,
 * temps `t`). Interpolation linéaire de `t` à exactement D côté départ. `null` si trace trop courte.
 */
export function bestSegmentTimeFromSamples(
  cum: ReadonlyArray<number>, t: ReadonlyArray<number>, targetDistanceM: number,
): number | null {
  const n = cum.length;
  if (n < 2 || cum[n - 1]! < targetDistanceM) return null;
  let best = Infinity;
  let k = 0;
  for (let j = 1; j < n; j++) {
    if (cum[j]! < targetDistanceM) continue;
    const s0 = cum[j]! - targetDistanceM;
    while (k + 1 < n && cum[k + 1]! <= s0) k++; // k = dernier index avec cum[k] <= s0
    const span = cum[k + 1]! - cum[k]!;
    const frac = span > 0 ? (s0 - cum[k]!) / span : 0;
    const tStart = t[k]! + frac * (t[k + 1]! - t[k]!);
    best = Math.min(best, t[j]! - tStart);
  }
  return best === Infinity ? null : best;
}

export function bestSegmentTime(points: ReadonlyArray<GpsPoint>, targetDistanceM: number): number | null {
  if (points.length < 2) return null;
  const cum = cumulativeDistances(points);
  const t = points.map((p) => p.t);
  return bestSegmentTimeFromSamples(cum, t, targetDistanceM);
}

/** Meilleurs temps par distance atteignable (clé absente si non atteignable). */
export function computeRunRecords(points: ReadonlyArray<GpsPoint>): Partial<Record<RecordDistanceKey, number>> {
  const out: Partial<Record<RecordDistanceKey, number>> = {};
  if (points.length < 2) return out;
  const cum = cumulativeDistances(points);
  const t = points.map((p) => p.t);
  for (const { key, meters } of RUNNING_RECORD_DISTANCES) {
    const time = bestSegmentTimeFromSamples(cum, t, meters);
    if (time != null) out[key] = time;
  }
  return out;
}
```
> ⚠️ Note pour l'implémenteur : le `k` est **monotone croissant** à travers les `j` (les fenêtres avancent), d'où le pointeur partagé — mais **vérifier** que `k` ne dépasse pas `j-...` ; comme `s0 < cum[j]`, on a toujours `k < j`. Ajuster le test « zone outlier » à la valeur exacte produite et documenter.
