### Tâche 1 — Hook `useMostRecentRecord()` (dashboard-repository)

**Fichier :** `apps/mobile/src/data/repositories/dashboard-repository.ts`.

- [ ] **Étape 1 — Implémenter** un hook réactif qui compose deux sources, **en respectant les piliers actifs** :
  - lire `settings.activePillars` (via `useSettings`) ;
  - muscu : `useQuery` sur `SELECT pr.type, pr.value, pr.achieved_at, et.name AS exercise_name
    FROM personal_records pr LEFT JOIN exercise_translations et ON et.exercise_id = pr.exercise_id
    AND et.locale = ? (COALESCE fr) WHERE pr.user_id = ? AND pr.deleted_at IS NULL
    ORDER BY pr.achieved_at DESC LIMIT 1` (reproduire le pattern de jointure/locale de `SELECT_RECORDS_FOR_WORKOUT`) ;
  - running : `useRunningRecords()` → prendre l'élément au `achievedAt` le plus récent ;
  - **filtrer** : ignorer la source muscu si `strength` non actif ; la source running si `running` non actif ;
  - **fusion** : retourner le plus récent des candidats restants, typé
    `{ pillar: 'strength' | 'running'; label: string; value: string; achievedAt: string } | null`
    (le `label`/`value` d'affichage peut être laissé à la carte ; a minima retourner les champs bruts
    nécessaires : type/valeur/exerciseName pour muscu, distanceKey/bestTimeSeconds pour running).
  - Hooks appelés **inconditionnellement** (les deux `useQuery`/hook running), filtrage sur les **résultats**.
  - Retour `{ record, isLoading }`.
- [ ] **Étape 2 — typecheck/lint verts.**
- [ ] **Étape 3 — Commit** : `feat(mobile): useMostRecentRecord (dernier record battu, piliers actifs)`.
