# Plan d'implémentation — Personnalisation du dashboard (V0.6, Lot B)

> Exécuter avec `superpowers:subagent-driven-development`. Spec validée :
> [docs/specs/functional/us/7.1-7.3-7.11-7.12-dashboard-personnalisation.md](../specs/functional/us/7.1-7.3-7.11-7.12-dashboard-personnalisation.md).
> Branche : `feature/dashboard-personnalisation`. **100 % client, aucune migration, testable USB.**

**Objectif :** mode édition du dashboard (réorganiser, masquer/afficher, redimensionner), disposition persistée
(local + cloud) via la colonne existante `user_settings.dashboard_layout`.

**Architecture :** logique pure dans `@wellness/shared` (registre + résolution + réordonnancement, testée) →
hook de persistance réutilisant `settings-repository` → variantes compactes des 7 widgets → conteneur d'édition
(drag & drop reanimated/gesture-handler) → intégration dans `(tabs)/index.tsx`.

## Fichiers touchés
- Créer : `packages/shared/src/dashboard.ts` + `dashboard.test.ts` ; exporter dans `index.ts`.
- Créer : `apps/mobile/src/data/repositories/dashboard-layout-repository.ts` (hook + mutateurs via `updateSettings`).
- Modifier : les 7 `apps/mobile/src/components/dashboard/*.tsx` (prop `size` + rendu compact).
- Créer : `apps/mobile/src/components/dashboard/DashboardEditControls.tsx` + conteneur sortable
  (`SortableDashboard.tsx` ou équivalent).
- Modifier : `apps/mobile/src/app/(tabs)/index.tsx` (rendu de la liste résolue + mode édition + drag).
- Modifier : `apps/mobile/src/i18n/locales/fr.json` + `en.json` (`home.customize.*`).

### Tâche 1 — Registre + logique pure (`@wellness/shared`) — TDD

**Fichiers :** créer `packages/shared/src/dashboard.ts` + `dashboard.test.ts` ; exporter dans `index.ts`.

- [ ] **Étape 1 — Test rouge** (`dashboard.test.ts`) couvrant :
  - `defaultDashboardLayout()` = 7 widgets, ordre canonique, `visible:true`, `size:'full'` ;
  - `resolveDashboardLayout(stored, activePillars)` : (a) `stored=null` → défaut filtré piliers ;
    (b) widget connu absent du stored → **ajouté en fin** `visible:true/full` ; (c) **filtre piliers**
    (widget d'un pilier inactif absent ; widget `always` jamais filtré) ; (d) **ID inconnu ignoré** ;
    (e) tri **par `order`** ; (f) `visible:false` conservé (y compris pour `always`) ;
  - `moveWidget(layout, id, toIndex)` : réordonne et **recompacte les `order`** (0..n-1), pur/immuable.
- [ ] **Étape 2 — Vérifier l'échec.**
- [ ] **Étape 3 — Implémenter** `DASHBOARD_WIDGET_IDS`, `DashboardWidgetId`, `WIDGET_PILLARS`
  (`Record<DashboardWidgetId, Pillar[] | 'always'>`), `WidgetSize`, `WidgetLayoutEntry`, `DashboardLayout`,
  `defaultDashboardLayout()`, `resolveDashboardLayout()`, `moveWidget()`. Zéro dépendance native/React.
- [ ] **Étape 4 — Vert.** Exporter dans `index.ts`.
- [ ] **Étape 5 — Commit** : `feat(shared): registre + résolution de layout dashboard (perso)`.

### Tâche 2 — Persistance (hook + mutateurs)

**Fichier :** créer `apps/mobile/src/data/repositories/dashboard-layout-repository.ts`.

- [ ] **Étape 1 — Implémenter** :
  - `useDashboardLayout()` → `{ layout, isLoading }` : lit `useSettings()`, **parse tolérant** du
    `settings.dashboardLayout` (fallback défaut si null/corrompu → via un `parseDashboardLayout` sûr, éventuellement
    dans shared), puis `resolveDashboardLayout(parsed, activePillars)` (activePillars depuis settings) ;
  - **mutateurs** persistants : `setLayout(next)`, `toggleVisible(id)`, `setSize(id, size)`, `reorder(id, toIndex)`
    → construisent le nouveau `DashboardLayout` (via helpers purs) et appellent
    `updateSettings({ dashboardLayout: next })`. **Débounce** (~400 ms) sur l'écriture pendant le drag.
  - Écrire **le layout complet non filtré** (toutes les entrées connues, y compris masquées) — le filtrage piliers
    est une préoccupation d'affichage, pas de stockage.
- [ ] **Étape 2 — typecheck/lint verts.**
- [ ] **Étape 3 — Commit** : `feat(mobile): persistance du layout dashboard (user_settings.dashboard_layout)`.

### Tâche 3 — Variante compacte des 7 widgets

**Fichiers :** les 7 `components/dashboard/*.tsx` + i18n si besoin.

- [ ] **Étape 1 — Ajouter une prop `size: WidgetSize`** à chaque carte (défaut `full`). En `compact`, rendu
  **une ligne** (titre court + valeur clé), gabarit commun (cf. maquette) :
  - `TodaySessionCard` → nom séance / « Séance libre » ; `NutritionSummaryCard` → kcal restantes ;
  - `StreakCard` → « N j » ; `WeightCard` → dernière pesée ; `RecordRecentCard` → record court ;
  - `MuscleVolumeCard` → total kg semaine ; `RunningWeekCard` → distance + séances.
  Réutiliser `DashboardCard` (ou un `DashboardCardCompact` partagé) pour la cohérence visuelle.
- [ ] **Étape 2 — typecheck/lint/tests verts.**
- [ ] **Étape 3 — Commit** : `feat(mobile): variante compacte des widgets dashboard (7.11)`.

### Tâche 4 — Contrôles d'édition (masquer/afficher, taille) sans drag

**Fichiers :** créer `DashboardEditControls.tsx` ; modifier `(tabs)/index.tsx`.

- [ ] **Étape 1 — Mode édition** : état local `editing` (`useState`), bouton « Personnaliser » / « Terminé »
  (emplacement selon maquette). En édition, chaque carte est enveloppée d'un overlay `DashboardEditControls`
  (bouton **œil** masquer/afficher — sur **tous** les widgets ; bascule **taille**). Les mutations appellent les
  mutateurs de la Tâche 2. Widgets masqués **listés en édition** (marqués), masqués hors édition.
- [ ] **Étape 2 — Rendu résolu** : `(tabs)/index.tsx` rend `layout` (résolu) via une **map `id → composant`**,
  en passant `size`. Hors édition : uniquement les `visible`. En édition : tous (résolus/filtrés piliers), les
  masqués marqués. a11y sur les contrôles.
- [ ] **Étape 3 — typecheck/lint/tests verts, parité i18n `home.customize.*`.**
- [ ] **Étape 4 — Commit** : `feat(mobile): mode édition dashboard — masquer/afficher + taille (7.1/7.3/7.11)`.

### Tâche 5 — Réorganisation par drag & drop (7.2)

**Fichiers :** conteneur sortable + `(tabs)/index.tsx`.

- [ ] **Étape 3 — Vérifier** : réorganisation persistée (débounce) ; ordre restauré au redémarrage ; pas de conflit

- [ ] **Étape 4 — typecheck/lint/tests verts.**
- [ ] **Étape 5 — Commit** : `feat(mobile): réorganisation du dashboard par drag & drop (7.2)`.

## Definition of Done (rappel spec §7)
- [ ] Logique pure (registre, `resolveDashboardLayout`, `moveWidget`) testée (fusion forward-compat, filtre piliers,
      ID inconnu, tri, réordonnancement, `visible` préservé).
- [ ] Mode édition : entrée/sortie ; **drag & drop** (sans scroll parasite) ; **masquer/afficher** (tous widgets,
      réaffichables depuis l'édition) ; **taille** compacte/normale sur les **7** widgets.
- [ ] Persistance `updateSettings({ dashboardLayout })` : survit au redémarrage, synchronisée. Débounce sur le drag.
- [ ] Widgets de piliers inactifs jamais affichés (vue **et** édition).
- [ ] i18n FR/EN parité ; a11y des contrôles. typecheck/lint/tests verts.
- [ ] **Aucune migration / checkpoint 🔴 cloud.** Testable USB. Revues (conformité + qualité) + PR relue.

## Notes
- **Réutilisation** : `settings-repository` (persistance), `DashboardCard`, les 7 widgets existants.
- **Débounce drag** : ~400 ms (valeur d'implémentation).
- **Drag from scratch** : pas de précédent dans l'app ; découpé en infra (5.1) + finitions (5.2) pour maîtriser le risque.
