# US 3.9 — Planning muscu daté + calendrier unifié — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Généraliser la couche de planification R3c-i (aujourd'hui running) en un **calendrier unifié pilier-agnostique** : planifier un programme muscu **ou** running, tout voir sur un seul écran « Mon planning » (séances des 2 piliers, indicateur de coordination même-jour), sans migration ni changement cloud.

**Architecture:** Réutilise `planned_sessions` (générique, déjà déployée) + `exercise_plans` (déjà synchronisé). Généralise le repository (`planProgram`, `useWeekPlan` tous piliers + `pillar`/`exerciseCount`, `useMissedSessions` tous piliers), renomme l'écran/route `running-planning → planning` et l'assistant, rend l'affichage **pilier-aware** (muscu = nom + N exercices ; running = type/cible/allure) + **indicateur ≥ 2 séances/jour**. **Contrainte forte : non-régression du running device-validé** (renommage i18n/route exhaustif, logique inchangée).

**Tech Stack:** `@wellness/shared` (schéma Zod), `apps/mobile` (Expo Router SDK 57, `useUnits`, i18next, React Compiler). Réutilise `planned-session-repository.ts`, `running-planning/`, `running-programs/plan.tsx`, `programs/[id].tsx`, `(tabs)/{running,strength}.tsx`. **Aucune migration, aucun cloud, aucune dépendance native.**

**Spec :** [3.9-planning-muscu-unifie.md](../specs/functional/us/3.9-planning-muscu-unifie.md) (validée). **Patrons :** R3c-i (`planRunningProgram`, `useWeekPlan`, écran running-planning, assistant plan.tsx).

**Branche :** `feature/us3.9-planning-unifie`, depuis `dev` (spec `b76313b`).

> **Invariants (rappel spec) :**
> - Dates calendaires 0=lundi, idempotence, activation par pilier — **repris tels quels** de R3c-i.
> - **Non-régression running** : à chaque commit, `npm run typecheck` + `npm run lint -w @wellness/mobile` + `npm run test` verts ; **grep de contrôle** à zéro occurrence résiduelle après renommage.
> - Coordination = **indicateur doux** (≥ 2 séances `planned`+`done`/jour), jamais bloquant.
> - **Ne jamais stager `apps/mobile/eas.json`.**

- [ ] **`SELECT_PLANNED_BETWEEN`** : joindre `programs` pour le pilier + compter les exercices de la séance :
```sql
SELECT ps.id, ps.program_id, ps.session_id, ps.scheduled_date, ps.status, ps.week_index,
       s.name AS session_name, s.session_type, s.target_distance_m, s.target_duration_seconds, s.order_index,
       p.pillar AS pillar,
       (SELECT COUNT(*) FROM exercise_plans ep WHERE ep.session_id = ps.session_id AND ep.deleted_at IS NULL) AS exercise_count
FROM planned_sessions ps
JOIN sessions s ON s.id = ps.session_id AND s.deleted_at IS NULL
JOIN programs  p ON p.id = ps.program_id AND p.deleted_at IS NULL
WHERE ps.owner_id = ? AND ps.deleted_at IS NULL
  AND ps.scheduled_date >= ? AND ps.scheduled_date <= ?
ORDER BY ps.scheduled_date, s.order_index
```
