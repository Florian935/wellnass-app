# Plan d'implémentation — US 4.7b (détection anticipée des jours d'entraînement)

> Exécuter avec `superpowers:subagent-driven-development`. Spec validée :
> [docs/specs/functional/us/4.7b-nutrition-jour-entrainement-anticipe.md](../specs/functional/us/4.7b-nutrition-jour-entrainement-anticipe.md).
> Branche : `feature/nutrition-4.7-anticipee` (rebasée sur `dev`).

**Objectif :** un jour avec une séance **planifiée** (`planned_sessions`, statut `planned`/`done`) compte
comme jour d'entraînement **par anticipation** (aujourd'hui + futur), déclenchant le bonus calorique
nutrition. Le passé reste rétroactif. Streak inchangé. **Aucune migration, aucun cloud, 100 % JS.**

**Architecture :** un helper pur testable dans `@wellness/shared` + un hook de lecture réactif
owner-scopé dans le repository planning + composition dans `useIsTrainingDay`. UI **inchangée**.

## Maquette

**Pas de nouvel écran ni de nouveau composant.** L'UI est strictement inchangée : le badge « +X kcal ·
jour de séance » et l'objectif majoré existent déjà (4.7) et sont pilotés par `useIsTrainingDay` ; on
élargit uniquement la **condition** qui l'active. Aucune maquette requise (justifié en DoD de la spec).

### Tâche 1 — Helper pur `isTrainingDay` (`@wellness/shared`)

**Fichiers :** créer `packages/shared/src/training-day.ts` + `training-day.test.ts` ; exporter dans `index.ts`.

- [ ] **Étape 1 — Test rouge.** Écrire `training-day.test.ts` couvrant la règle
  `retroactiveDone || (hasPlanned && dayKey >= todayKey)` :
  - passé + fait rétroactif (`retroactiveDone=true`, dayKey<today) → `true` ;
  - passé + seulement planifié (`retroactiveDone=false, hasPlanned=true`, dayKey<today) → `false` (pas d'anticipation dans le passé) ;
  - **aujourd'hui** planifié (`hasPlanned=true, dayKey===todayKey`) → `true` (**cas frontière**) ;
  - futur planifié (`hasPlanned=true`, dayKey>today) → `true` ;
  - futur sans rien → `false` ;
  - aucun signal → `false`.
- [ ] **Étape 2 — Vérifier l'échec** (`npm run test` côté shared : import inexistant).
- [ ] **Étape 3 — Implémenter** :
  ```ts
  export interface TrainingDayInput {
    /** Une séance muscu/course a été TERMINÉE ce jour-là (rétroactif, tout jour). */
    retroactiveDone: boolean;
    /** Une séance est PLANIFIÉE ce jour-là (statut planned|done). */
    hasPlanned: boolean;
    /** Jour évalué, `AAAA-MM-JJ` (clé locale). */
    dayKey: string;
    /** Aujourd'hui, `AAAA-MM-JJ` (clé locale). */
    todayKey: string;
  }
  /**
   * Un jour est « jour d'entraînement » si une séance y a été FAITE (rétroactif,
   * tout jour) OU si une séance y est PLANIFIÉE et que le jour est aujourd'hui ou
   * futur (anticipation). Le passé n'est jamais anticipé. Comparaison de clés
   * `AAAA-MM-JJ` (lexicographique = chronologique).
   */
  export function isTrainingDay(i: TrainingDayInput): boolean {
    return i.retroactiveDone || (i.hasPlanned && i.dayKey >= i.todayKey);
  }
  ```
- [ ] **Étape 4 — Vérifier le vert** (`npm run test`).
- [ ] **Étape 5 — Commit** : `feat(shared): helper pur isTrainingDay (jour d'entraînement anticipé)`.

### Tâche 2 — Hook `useHasPlannedSession(dayKey)` (repository planning)

**Fichier :** modifier `apps/mobile/src/data/repositories/planned-session-repository.ts`.

- [ ] **Étape 1 — Implémenter** un hook réactif owner-scopé, sur le patron exact de `useWeekPlan`
  (`useAuthStore((s) => s.session?.user.id ?? '')` + `useQuery`) :
  ```ts
  const SELECT_HAS_PLANNED = `
    SELECT 1 AS has FROM planned_sessions
    WHERE owner_id = ? AND scheduled_date = ?
      AND status IN ('planned','done') AND deleted_at IS NULL
    LIMIT 1`;

  export function useHasPlannedSession(dayKey: string): {
    hasPlanned: boolean;
    isLoading: boolean;
  } {
    const userId = useAuthStore((s) => s.session?.user.id ?? '');
    const { data, isLoading } = useQuery<{ has: number }>(SELECT_HAS_PLANNED, [
      userId,
      dayKey,
    ]);
    return { hasPlanned: (data?.length ?? 0) > 0, isLoading };
  }
  ```
  (Aligner le nom de colonne `scheduled_date` / `owner_id` / `status` sur les requêtes existantes du
  fichier. Vérifier la casse des statuts `'planned'`/`'done'`.)
