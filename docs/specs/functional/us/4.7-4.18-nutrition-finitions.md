# US 4.7 + 4.18 — Finitions Nutrition (calories jour de séance · copier une journée)

> Finitions de la **V0.4 — Alimentation** : deux items restés « différés » dont la logique
> pure était déjà posée, à brancher côté UI.
> Réf. pilier : [alimentation.md](../alimentation.md) · Archi : pattern repository, offline-first.
> Branche : `feature/nutrition-finitions-4.7-4.18` · Date : 12/07/2026.

## 1. Contexte & objectif

Deux fonctionnalités de la roadmap V0.4 sont **codées à moitié** :

- **4.7 — Calories adaptées à l'entraînement** : le champ `trainingDayBonus` existe en base
  (`nutrition_profiles.training_day_bonus`, défaut `0`) et la fonction pure
  `trainingDayCalories(target, bonus)` est écrite et testée dans `@wellness/shared`, mais **rien ne
  la branche** : le bonus n'est ni réglable dans l'UI, ni appliqué à l'objectif du jour.
- **4.18 — Copier une journée** : `copyMeal` (copier un repas depuis la veille) est branché, mais
  `duplicateDay(fromDate, toDate)` (dupliquer **toute** une journée) existe dans le repo **sans
  point d'entrée UI**.

**Objectif** : rendre ces deux fonctions accessibles et correctes, sans nouvelle dépendance ni
nouveau build natif (100 % client, testable sur le dev build actuel).

## 2. Décisions produit (validées 12/07/2026)

### 4.7 — Jour d'entraînement
- **Définition d'un « jour d'entraînement »** (décision Damien 12/07) : un jour est « de séance »
  s'il porte **au moins une séance muscu terminée OU une course terminée** (`status = 'completed'`).
  → détection **rétroactive** : faute de planning muscu daté (item 3.9 différé en US2b), on ne peut
  pas anticiper. **L'objectif monte donc une fois la séance enregistrée** ce jour-là. Comportement
  assumé pour le MVP ; passera en anticipé quand le planning existera.
- **Bonus réglable** : nouveau champ numérique « Bonus jour d'entraînement (kcal) » dans l'écran
  profil nutritionnel, sous le bloc calories. `0` (ou vide) = fonctionnalité **désactivée**
  (aucun bonus, aucun badge). Entier ≥ 0.
- **Application** : l'objectif **calorique** effectif du jour devient
  `trainingDayCalories(objectifBase, bonus)` **si** (jour de séance ET bonus > 0). Sinon inchangé.
  - Concerne : l'objectif + le « restant » du **journal** (onglet Nutrition, jour affiché) et le
    **widget dashboard** (aujourd'hui uniquement).
  - **Les macros cibles restent sur l'objectif de base** (le bonus est un supplément calorique non
    ventilé en P/G/L — évite d'inventer une répartition). Assumé pour le MVP.
- **Indication visuelle** : quand le bonus s'applique, un **badge discret** « Jour de séance
  +X kcal » sous la ligne calories (journal + widget). Sans badge quand il ne s'applique pas.

### 4.18 — Copier une journée
- **Point d'entrée** : bouton « Copier la journée d'hier » dans l'onglet Nutrition, visible
  **uniquement quand le jour affiché est vide** (aucune entrée) — évite les doublons involontaires
  et garde l'écran propre quand il est déjà rempli.
- **Action** : `duplicateDay(hier, jourAffiché)` copie **toutes** les entrées de la veille (tous
  repas, snapshot des valeurs, comme `copyMeal`). Retour = nombre d'entrées copiées.
- **Rien à copier** : si la veille est vide (`0`), afficher un message neutre (aucun changement,
  pas d'erreur).

## 3. Règles métier & cas limites

- **Fuseau horaire / offline** : les séances/courses stockent `finished_at` en **UTC ISO** ; le
  journal indexe par **jour local** (`log_date`). La détection borne la requête sur
  `[minuit local du jour, minuit local du lendemain[` converti en UTC (`Date(dayKey+'T00:00:00')`
  → `toISOString()`), cohérent avec `localDayKey`. Pas de comparaison de chaîne UTC ↔ locale.
- **Séance active non terminée** : ne compte pas (filtre `status = 'completed'`).
- **Soft delete** : `deleted_at IS NULL` sur workouts et runs.
- **Réactivité** : détection via `useQuery` PowerSync → l'objectif se met à jour dès qu'une séance
  est clôturée, sans rechargement.
- **Pilier running non activé** : la table `runs` existe quand même (vide) → requête sûre.
- **Bonus = 0** : aucun calcul, aucun badge (chemin identique à l'existant → zéro régression).
- **4.18 jour non vide** : bouton masqué → pas de risque de double-copie.
- **i18n FR + EN** : toutes les nouvelles chaînes (badge, bouton copier, label bonus, message
  « rien à copier ») en miroir FR/EN.

## 4. Hors périmètre

- Objectif **anticipé** (avant la séance) → nécessite le planning muscu (US2b).
- Ventilation du bonus en macros ; bonus par **type** de séance ; bonus running distinct du muscu.
- Édition de la journée copiée avant validation (copie directe, éditable ensuite comme d'habitude).
- 100 % client → **aucun checkpoint cloud** (pas de migration ; `training_day_bonus` déjà en base
  et déployé avec l'US4.1).
