# US 8.2 — Admin : CRUD des exercices éditoriaux (+ brouillon/publié)

> Gérer les **exercices éditoriaux** depuis le back-office : lister, créer, éditer (bilingue FR+EN),
> **brouillon/publié**, archiver. Suite de l'Admin F1/F2. Branche : `feature/admin-8.2-exercices-crud` ·
> Date : 13/07/2026. **⚠️ 🔴 checkpoint cloud** : migration RLS/status **+ redéploiement des sync rules** + `db:types`.

## 0. Contexte (exploration)

- `exercises` : `id`, `owner_id` (NULL = **éditorial**), `source` ('library'/'custom'), `muscle_primary`
  (chest/back/legs/shoulders/arms/core), `equipment` (texte, nullable), `media_url` (nullable — **upload = 8.3**),
  timestamps, `deleted_at`. **Aucune colonne statut aujourd'hui.**
- `exercise_translations` : `(exercise_id, owner_id, lang 'fr'|'en', name, instructions nullable)`, **une ligne par
  langue** (unique `(exercise_id, lang)`), `deleted_at`.
- Schémas Zod (`exercise.ts` : `MUSCLE_GROUPS`, `ExerciseRow`, `ExerciseTranslationRow`) + `database.types`
  **réutilisables** côté admin.
- **RLS actuelle** : `select (owner_id is null or owner_id = auth.uid())` ; `insert/update (owner_id = auth.uid())`
  → **l'admin ne peut pas écrire l'éditorial**. Fonctions F2 `public.is_admin()`/`is_super_admin()` disponibles.
- **Mobile** (`exercise-repository.ts`) lit tous les exercices `deleted_at IS NULL` via **PowerSync** (bucket
  `shared_content` pour l'éditorial). Pas de filtre statut aujourd'hui.
- Admin = web, **supabase-js direct** (session admin, gated RLS). UUID générés client (`crypto.randomUUID()`).

## 1. Périmètre à livrer

Dans `apps/admin`, un module **Exercices** (réservé aux rôles admin — `content_editor`/`super_admin`) :
- **Lister** les exercices éditoriaux (nom FR, groupe, statut) + recherche + filtre par groupe/statut.
- **Créer** un exercice éditorial : groupe musculaire, équipement (optionnel), **nom FR + nom EN requis**,
  instructions FR/EN (optionnelles), **statut** (brouillon par défaut).
- **Éditer** (mêmes champs) + **publier / repasser en brouillon**.
- **Archiver** (soft-delete) avec confirmation.
- **Brouillon/publié** : un exercice **brouillon** n'est **jamais synchronisé au mobile** (filtré dans les sync
  rules) ; **publié** = visible dans la biblio mobile. **Aucun changement de code mobile.**

**Hors périmètre / différé :**
- **Upload média** (GIF/image, `media_url`) → **US 8.3** (le formulaire laisse `media_url` vide au MVP).
- Muscles secondaires (le modèle n'a que `muscle_primary`).
- CRUD des exercices **utilisateur** (`owner_id = user`) — hors admin (gérés dans l'app mobile).
- Constructeur de programmes (8.4), aliments (8.5)…

## 2. Modèle de données — migration (🔴 cloud)

Migration `20260713xxxxxx_admin_editorial_exercises.sql` :
- **Colonne statut** : `alter table public.exercises add column status text not null default 'published'
  check (status in ('draft','published'))`. Défaut `'published'` → seed + customs existants restent visibles ;
  seuls les **nouveaux brouillons éditoriaux** sont masqués.
- **RLS `exercises`** :
  - **select** (remplace l'actuelle) :
    `using (owner_id = auth.uid() or (owner_id is null and status = 'published') or public.is_admin())`
    → un user voit l'éditorial **publié** + ses propres exercices ; un **admin** voit tout (dont brouillons).
  - **insert** : `with check (owner_id = auth.uid() or public.is_admin())`.
  - **update** : `using (...) with check (owner_id = auth.uid() or public.is_admin())` (couvre publish/brouillon
    et le soft-delete = update de `deleted_at`).
- **RLS `exercise_translations`** : insert/update → ajouter `or public.is_admin()` (idem).
- **`database.types.ts`** : ajouter `status` à `exercises` (Row/Insert/Update) — manuel, idempotent avec `db:types`.

## 3. Sync rules (🔴 cloud) — masquer les brouillons au mobile

Dans [powersync-sync-rules.yaml](../../technical/powersync-sync-rules.yaml), le bucket `shared_content` qui
synchronise l'éditorial : la requête sur `exercises` doit filtrer **`status = 'published'`** (en plus de
`deleted_at is null`). → les brouillons éditoriaux **ne descendent jamais** sur les appareils. Les exercices
`custom` (bucket `user_data`, owner-scopé) ne sont pas concernés (toujours synchronisés à leur propriétaire).
**Redéploiement des sync rules** sur PowerSync requis. **Aucun changement du schéma/queries mobile** (le mobile ne
reçoit que du publié ; la colonne `status` n'a pas besoin d'être déclarée côté client).

## 4. Comportement (admin)

- **Accès** : module « Exercices » dans la nav admin, visible pour un rôle admin (F2 gate) ; l'écran est protégé.
- **Liste** : tableau (nom FR, groupe musculaire, statut brouillon/publié, date) trié récent → ancien ;
  recherche par nom ; filtres groupe + statut ; états loading/vide. Ne liste que l'**éditorial**
  (`owner_id is null`, non supprimé) — l'admin les voit tous (RLS admin).
- **Créer / éditer** (formulaire) :
  - **Groupe musculaire** (select parmi `MUSCLE_GROUPS`) — requis.
  - **Équipement** (texte libre) — optionnel.
  - **Nom FR** + **Nom EN** — **les deux requis** (le mobile attend les deux ; publication bloquée sinon).
  - **Instructions FR / EN** — optionnelles.
  - **Statut** : brouillon (défaut à la création) / publié ; bouton **Publier** / **Repasser en brouillon**.
  - Écriture **séquentielle** supabase-js (pattern du repo mobile) : upsert `exercises` (owner_id NULL,
    source 'library', muscle_primary, equipment, status) + upsert des 2 `exercise_translations` (fr, en).
    UUID client pour les nouvelles lignes. Erreurs surfacées (FR).
- **Archiver** : confirmation → soft-delete de l'exercice **et** de ses traductions (`deleted_at = now`).
- **Publier** : passe `status='published'` (→ synchronisé au mobile au prochain sync). **Repasser en brouillon** :
  `status='draft'` (→ retiré de la synchro éditoriale ; disparaît de la biblio mobile).

## 5. Architecture (code, `apps/admin`)
- **`src/data/exercises.ts`** : `listEditorialExercises()` (join translations, éditorial, non supprimé),
  `getExercise(id)`, `saveExercise(input)` (create/update exercice + 2 traductions, séquentiel), `setStatus(id, status)`,
  `archiveExercise(id)` (soft-delete exercice + traductions). Typé via `Database` + réutilise `MUSCLE_GROUPS`/Zod de `@wellness/shared`.
- **`src/screens/ExercisesScreen.tsx`** (liste) + **`src/screens/ExerciseEditScreen.tsx`** (formulaire créer/éditer)
  ou un modal. Routing sous `RequireAdmin` + `AdminLayout` (`/exercises`, `/exercises/new`, `/exercises/:id`).
- **`AdminLayout`** : activer l'entrée « Exercices » (déjà présente en « bientôt » → la rendre cliquable pour un admin).
- **i18n** `fr.ts` : `exercises.*` (liste, colonnes, formulaire, statuts, actions, erreurs, confirmations).
- **Migration** + **sync rules** (voir §2/§3). **Pas de code mobile.**

## 6. Sécurité
- RLS = frontière : seul un admin (F2) peut écrire l'éditorial ; un user non-admin ne voit que le publié + le sien.
- Clé anon seule ; `service_role` interdit. Soft-delete uniquement (pas de hard delete).
- Un brouillon éditorial n'est jamais exposé au mobile (filtré au niveau sync).
