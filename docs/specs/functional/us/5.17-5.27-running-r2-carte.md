## 0. Contexte

R1 (livré, validé device) enregistre la course et **stocke la trace GPS encodée** sur la ligne `run`
(colonne `gps_track`, format polyline + deltas de temps, décodable via `decodeTrack()` →
`GpsPoint { lat, lng, t }`). R1 **n'affiche aucune carte**. R2 ajoute le **rendu cartographique**
du parcours, en direct pendant la course (5.17) et au résumé (5.27), avec MapLibre + tuiles MapTiler.

## 2. Comportement attendu

1. **Écran de suivi (live)** :
   - La carte affiche le **tracé accumulé** (décodé depuis `gpsTrack`, puis simplifié) + un **marqueur** à la dernière position.
   - **Réactif** : le tracé s'étend à chaque flush du tracker (~1 pt/s) sans recharger la carte.
   - **Caméra suit** la position courante (recentrage doux — API `Camera` de MapLibre, `followUserLocation` ou `setCamera` sur le dernier point).
   - **Deux états « sans tracé » distincts** (le composant reçoit un tableau de points vide ; c'est **l'écran** qui choisit le message selon `run.source` et l'état GPS) :
     - **Course GPS sans point encore** (fix non acquis / perdu, `source='gps'`, `points` vide) → « En attente du signal GPS… ».
     - **Course manuelle** (`source='manual'`, jamais de trace) → « Aucun tracé GPS pour cette course ».
   - La carte ne doit **pas dégrader** le tracking (perf/batterie) : rendu léger, pas de rechargement de tuiles superflu.
2. **Écran de résumé** :
   - Carte **statique** (non-suivie) **ajustée aux bornes** de la trace complète (`fitBounds` avec padding raisonnable).
   - Nécessite l'exposition de `gpsTrack` dans `RunDetail` (aujourd'hui absent) — voir §4 (changement en **3 endroits coordonnés**, pas seulement le type).
   - **Course manuelle** (source `manual`, pas de trace) ou trace vide → **pas de carte**, message discret « Aucun tracé GPS pour cette course ».
3. **Hors-ligne** : si les tuiles ne se chargent pas (pas de réseau), la carte affiche un fond neutre/placeholder **sans bloquer** l'écran ; toutes les autres infos (distance, allure, RPE…) restent affichées. Le **tracking et l'enregistrement ne dépendent jamais du réseau**.

## 3. Règles métier / techniques

- **Simplification** : `simplifyTrack(points: GpsPoint[], epsilonMeters): GpsPoint[]` (Douglas-Peucker) — **retourne des `GpsPoint`** (conserve `.t`, reste compatible avec le prop `points: GpsPoint[]` de `RouteMap`). Appliqué **à l'affichage uniquement** ; la trace **stockée reste complète** (aucune perte en base). ε ≈ 5 m par défaut, ajustable au device.
- **Décodage** : réutiliser `decodeTrack(gpsTrack)` existant ; ne décoder/simplifier que quand `gpsTrack` change (mémoïsation, comme l'écran actif le fait déjà).
- **Clé MapTiler** : lue via `process.env.EXPO_PUBLIC_MAPTILER_KEY` (comme les autres `EXPO_PUBLIC_*`) ; **jamais committée** ; ajoutée à `.env.example` + **EAS Environment Variables** (preview/production). Si la clé est absente → carte en placeholder + log, jamais de crash.
- **Attribution** obligatoire et lisible (© OpenStreetMap · © MapTiler).
- **Polyline** : couleur = accent du thème ; largeur lisible ; le marqueur de position courante distinct.
- **Perf** : sur une course longue (~1 h ≈ 3600 pts bruts), après simplification quelques centaines de points max ; pas de re-render de toute la carte à chaque frame.

## 4. Architecture

- **Dépendance** : `@maplibre/maplibre-react-native` + **config plugin** dans `apps/mobile/app.json` (array `plugins`). **Module natif → nouveau dev/preview build requis** (comme PowerSync/expo-location/expo-camera).
- **`@wellness/shared`** : ajouter `simplifyTrack(points, epsilonMeters)` (Douglas-Peucker, **pur, testé** ; distance perpendiculaire en mètres via approximation équirectangulaire suffisante à cette échelle). Réutilise `GpsPoint`.
- **`RunDetail`** ([run-repository.ts](../../../apps/mobile/src/data/repositories/run-repository.ts)) : exposer `gpsTrack` demande **3 changements coordonnés** (la requête ne sélectionne PAS `gps_track` aujourd'hui) : (1) ajouter `gps_track` à la constante SQL `SELECT_RUN_BY_ID` ; (2) ajouter `gps_track: string | null` à `RunDetailDbRow` ; (3) ajouter `gpsTrack: string | null` au type exporté `RunDetail` + le mapper `rowToRunDetail`. Sans le SQL, le champ serait `undefined` au runtime **sans erreur de compilation**.
- **Composant carte réutilisable** `apps/mobile/src/components/running/RouteMap.tsx` : props `{ points: GpsPoint[]; follow?: boolean; emptyLabel: string }` — si `points.length >= 1` : rend le fond MapLibre + la polyline (+ marqueur de position si `follow`, sinon `fitBounds` sur la trace) ; si `points` vide : rend un état neutre affichant `emptyLabel` (fourni par l'écran, cf. §2). Gère aussi l'absence de clé MapTiler (placeholder + log, jamais de crash). Consommé par `run/active.tsx` (`follow`, `emptyLabel` = attente GPS/manuel) et `run/summary.tsx` (fit bounds, `emptyLabel` = pas de tracé).
- **Écrans** : `run/active.tsx` insère `<RouteMap points={simplified} follow />` ; `run/summary.tsx` insère `<RouteMap points={simplified} />` (après avoir décodé `run.gpsTrack`).
