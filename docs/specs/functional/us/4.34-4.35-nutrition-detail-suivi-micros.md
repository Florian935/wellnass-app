# US 4.34 + 4.35 — Détail d'une entrée & suivi de micronutriments (récap)

> Continuation de la **V0.4 — Alimentation**, après le socle micronutriments (4.33).
> Réf. pilier : [alimentation.md](../alimentation.md) · Réutilise `MicronutrientDetails`,
> `sumMicronutrients`, `MICRONUTRIENT_KEYS` (posés en 4.33).
> Branche : `feature/nutrition-detail-suivi-micros` · Date : 12/07/2026.
> **100 % client** — aucune migration, aucun checkpoint cloud 🔴.

## 1. Contexte & objectif

Deux améliorations du journal alimentaire, indépendantes mais complémentaires (toutes deux
exposent davantage la donnée nutritionnelle déjà stockée) :

- **4.34 — Détail d'une entrée de journal** : aujourd'hui, dans l'onglet Nutrition, une entrée
  d'aliment ne réagit qu'à l'**appui long** (suppression). On veut pouvoir **taper** une entrée
  pour **consulter son détail** (macros + micronutriments **de la quantité journalisée**).
- **4.35 — Suivi de micronutriments dans le récap** : le récap du jour n'affiche que P/G/L. On veut
  pouvoir **choisir certains micronutriments** (parmi les 10 du socle 4.33) et voir leur **total du
  jour** aux côtés des macros.

## 2. Décisions produit (validées 12/07/2026)

### 4.34 — Détail d'une entrée
- **Cible** : les **entrées du journal** (aliments déjà journalisés), pas les résultats de recherche
  (le food-picker ouvre déjà un panneau détaillé à l'ajout).
- **Interaction** : **tap** = ouvrir le détail ; **appui long** = supprimer (conservé). Le détail
  s'ouvre en **modal** dans l'écran (donnée déjà en mémoire, lecture seule — pas de route ni de
  re-requête).
- **Contenu du détail** = **snapshot de l'entrée** (ce qui a été mangé pour la quantité) : nom,
  quantité (g), `kcal` + protéines / glucides / lipides, puis le bloc **micronutriments** de la
  quantité (réutilise `MicronutrientDetails`). **Seuls les nutriments présents** s'affichent ; sel
  dérivé sous le sodium (règle 4.33).
- **Source = snapshot** (et non l'aliment courant) : cohérent avec « l'historique n'est pas
  recalculé ». Les valeurs affichées sont celles figées à l'ajout, déjà à l'échelle de la quantité —
  donc **pas de ligne “pour 100 g”** dans ce contexte (elle n'a de sens qu'à la saisie).

### 4.35 — Suivi de micronutriments
- **Sélection** : l'utilisateur choisit les micros à suivre parmi les **10 clés** de
  `MICRONUTRIENT_KEYS` (4.33). Réglage dans l'écran **profil nutritionnel** (chips à bascule, patron
  des restrictions). Défaut : **aucun** suivi (le récap reste identique tant que rien n'est choisi).
- **Affichage** : dans le **récap du jour** (carte totaux de l'onglet Nutrition), sous les barres
  P/G/L, une ligne compacte par micro suivi = **total du jour** (`sumMicronutrients` des entrées du
  jour) + unité. **Totaux seuls, sans objectif/RDA** (cohérent avec 4.33 §non-objectif).
- **Un micro suivi sans donnée ce jour** → total `0` affiché (le suivi est explicite, on montre la
  ligne même à 0, contrairement au détail d'aliment qui masque les absents).
- **Stockage de la sélection = préférence locale (device)** via un store Zustand persisté par
  `lib/secure-storage`. **Non synchronisée entre appareils** (tradeoff assumé pour rester
  cloud-free) ; promotion possible vers `user_settings` synchronisé plus tard = petite migration.

## 3. Règles métier & cas limites

- **4.34** — entrée à `foodId` null (aliment perso / quick-add) : le détail marche quand même
  (snapshot autoportant). Aucune dépendance à l'aliment source.
- **4.34** — entrée sans aucun micro renseigné : le bloc micronutriments affiche son **état vide**
  (déjà géré par `MicronutrientDetails`).
- **4.35** — total du jour = somme des `micronutrients` (snapshots) de toutes les entrées du jour
  affiché (respecte la navigation entre jours 4.22). Réactif (`useQuery`).
- **4.35** — sel : si `sodium_mg` est suivi, afficher aussi le **sel dérivé** (`saltFromSodiumMg`)
  comme dans le détail (cohérence).
- **Offline** : 100 % lecture locale (snapshots PowerSync) + préférence locale → marche hors-ligne.
- **i18n FR + EN** : libellés micros/unités **déjà présents** (`nutrition.micros.*`, posés en 4.33).
  Nouvelles chaînes : titres modal détail, section « Micronutriments suivis » + hint.

## 4. Hors périmètre

- Objectifs / RDA par micronutriment (totaux seuls).
- Suivi des **sucres / fibres / AG saturés** (non figés dans `food_entries` → nécessiterait une
  migration ; explicitement écarté 12/07).
- Micros des **recettes / repas types** (agrégat basé sur les entrées de journal uniquement).
- Détail depuis les **résultats de recherche** (le panneau quantité couvre déjà ce besoin).
- Sélection **synchronisée** entre appareils (préférence locale pour ce lot).
- Historique/moyennes de micros dans `nutrition-stats` (récap du **jour** seulement ici).
