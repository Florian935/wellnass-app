# US Running R3b-ii — Bibliothèque de programmes de course + filtres

> Second incrément de **R3b** (après R3b-i programme custom). Bibliothèque de programmes de course
> pré-construits (5.2) + filtres (5.3). Réutilise l'infra bibliothèque muscu (`owner_id NULL` +
> `status='published'`, bucket `shared_content`, `useProgramLibrary`, `duplicateProgram`, pattern seed).
> Réf. : [running.md](../running.md) §3.2/§3.3. Branche : `feature/running-r3b2-bibliotheque` ·
> Date : 12/07/2026 · **Statut : à valider (pas de code avant validation).**

## 0. Contexte

L'infra **bibliothèque** existe déjà (muscu) et est réutilisable :
- Programmes éditoriaux = `programs` avec `owner_id NULL` + `status='published'` ; synchronisés à tous via le bucket **`shared_content`**.
- `useProgramLibrary(filters?)` (filtre `owner_id IS NULL`, `status='published'`, + `level`/`goal`/`durationWeeks`) — **mais pas le pilier** (à ajouter).
- `duplicateProgram(sourceId)` → **copie éditable** appartenant à l'utilisateur (déjà étendu R3b-i pour recopier le contenu running).
- Pattern **seed** (`seed.sql`) : `programs` + `program_translations` (FR+EN) + `sessions` (owner_id null), UUID déterministes, idempotent `ON CONFLICT DO NOTHING`.

R3b-ii ajoute : le **filtre pilier** sur la bibliothèque, un **écran bibliothèque running** (parcours + filtres + « utiliser »), et **2-3 programmes seedés**.

## 1. Périmètre à livrer

- **Écran bibliothèque running** : parcourir les programmes de course publiés (nom, résumé, objectif, niveau, durée), **filtrables** par **objectif** (`RUNNER_OBJECTIVES`), **niveau** (beginner/intermediate/advanced), **durée** (semaines). Intégré comme **onglet « Bibliothèque »** dans `running-programs` (à côté de « Mes programmes »), sur le patron de l'index programmes muscu.
- **« Utiliser ce programme »** : `duplicateProgram(sourceId)` → crée une **copie dans « Mes programmes »** (éditable), puis navigue vers son détail (l'utilisateur peut ensuite l'activer/personnaliser). *(Décision : duplication, pas d'activation directe du programme partagé.)*
- **Filtre pilier** ajouté à `useProgramLibrary` (running uniquement).
- **Seed** : **2-3 programmes de course « starter »** (bilingues FR+EN), avec leurs séances (type + cible), marqués comme **contenu de départ** à enrichir. Ex. : « 10 km en 8 semaines » (débutant), « Prépa semi-marathon » (~10-12 sem, régulier), « Reprise / endurance » (~6 sem).

**Hors périmètre :**
- **Contenu curé/étendu** (plans détaillés par un coach, nombreux programmes) → **tâche contenu ultérieure** (les 2-3 seedés sont un socle simple et défendable).
- Blocs d'intervalles (différés R3b-i), planning/calendrier (R3c), progression automatique de volume, visualisation de la charge (running.md §3.2 dernier point) → différés.
- Édition des programmes **bibliothèque** eux-mêmes (éditorial) : hors app (seed/back-office V0.7).

## 2. Comportement attendu

1. **Onglet Bibliothèque** (dans `running-programs`) : liste des programmes publiés running ; barre de **filtres** (objectif / niveau / durée) ; chaque carte affiche nom + résumé + chips (objectif, niveau, durée) + bouton **« Utiliser »**.
2. **Filtrer** : combine les critères (ET) ; liste réactive.
3. **« Utiliser »** → `duplicateProgram` → toast/confirmation + navigation vers le détail de la **copie** dans « Mes programmes ». Le programme bibliothèque source reste intact.
4. **Réactif** (`useQuery`) ; **offline-first** (le contenu bibliothèque est synchronisé via `shared_content`, dispo hors-ligne une fois synchronisé).

## 3. Règles métier

- **Filtre pilier** : `useProgramLibrary` accepte le pilier (running) ; ne mélange jamais muscu et running (le `goal` sert aux deux, seul le pilier discrimine).
- **Objectif** : filtre sur `programs.goal` (valeur `RUNNER_OBJECTIVES`) ; **niveau** sur `programs.level` dont l'**enum est `beginner` / `intermediate` / `advanced`** (valeurs BDD ; libellés i18n `running.programLevel.*` = « Débutant / **Régulier** / Confirmé » — « Régulier » = `intermediate`, jamais de valeur `regular`) ; **durée** sur `duration_weeks`.
- **Utiliser = dupliquer** : la copie a `owner_id = utilisateur` et **doit être `is_active=false`** (l'utilisateur active ensuite). ⚠️ **Le plan doit vérifier le comportement réel de `duplicateProgram`** (statut/`is_active` de la copie) avant de câbler le toast/navigation — la copie ne doit pas arriver active. `duplicateProgram` recopie déjà traductions + séances + **contenu running** (R3b-i).
- **Seed idempotent** : UUID déterministes, `ON CONFLICT DO NOTHING` ; programmes `owner_id NULL`, `status='published'`, `pillar='running'` ; séances avec `session_type` + cible (`target_distance_m` ou `target_duration_seconds`) respectant la check constraint R3b-i. Contenu **simple et raisonnable** (pas de plan agressif), FR + EN.
