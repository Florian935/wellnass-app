## 0. Contexte & problème

Aujourd'hui l'écran d'accueil ([apps/mobile/src/app/(tabs)/index.tsx](../../../apps/mobile/src/app/(tabs)/index.tsx))
est un **placeholder statique** : les trois cartes (Séance du jour, Régularité, Nutrition) affichent
toujours un état vide **non branché aux données**, streak figé à `0`, et la carte Nutrition annonce
« le journal alimentaire arrive bientôt » — message **désormais faux** (le journal est livré en V0.4).

Cette US branche le dashboard sur les vraies données locales (PowerSync/SQLite), conformément à
navigation-ux §3. **Hors périmètre ici** (US suivante) : la couche de **personnalisation** (7.1 mode
édition, 7.2 drag & drop, 7.3 masquer, 7.11 tailles, 7.12 persistance de disposition). On livre des
widgets **fixes** mais réels.

## 2. Règles métier

- **Streak (navigation-ux §3.2)** : jour actif = ≥ 1 **séance terminée** (muscu/running) **ou** **journée
  nutrition complétée** (tous les repas actifs de la config saisis). Jour de **repos prévu** par le
  programme = **neutre** (ne casse ni n'incrémente). Bascule à **minuit, fuseau local**. Un changement
  de fuseau ne casse **jamais** un streak rétroactivement (calcul le plus favorable en cas d'ambiguïté).
- **Séance du jour** : si plusieurs séances planifiées, afficher la **prochaine non terminée**. Une séance
  déjà `active` prend le pas (CTA « Reprendre »).
- **Résumé nutrition** : objectif = objectif du jour du profil nutritionnel (incluant le bonus jour
  d'entraînement s'il s'applique, cf. `training_day_bonus`). « restantes » = objectif − consommé (peut être négatif).
- **Temps réel** : le dashboard se met à jour en direct (hooks réactifs `useQuery` PowerSync) — ex. pendant une séance.

## 3. Cas limites

- Aucun pilier autre qu'Accueil actif → n'afficher que les widgets pertinents (jamais de carte vide).
- Profil nutritionnel non défini → carte Nutrition en état vide avec CTA « Définir mon objectif ».
- Aucune pesée → carte Poids en état vide (« Aucune pesée ») + CTA.
- Running non encore livré (V0.5) → le streak se calcule sur muscu + nutrition ; brancher running quand disponible.
- Premier lancement : le dashboard **guide vers la 1ʳᵉ action utile** selon les piliers actifs (navigation-ux §4.4).
