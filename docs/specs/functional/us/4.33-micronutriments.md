# US 4.33 — Micronutriments (enrichissement des données nutritionnelles)

> US complémentaire de la **V0.4 — Alimentation** (après 4.1 / 4.8 / 4.10 / 4.24).
> Réf. pilier : [alimentation.md](../alimentation.md) §3 (base d'aliments) · Archi data : pattern repository.
> Branche : `feature/4.33-micronutriments` · Date : 11/07/2026.

## 1. Contexte & objectif

Aujourd'hui un aliment ne porte que **7 valeurs pour 100 g** (`kcal` + protéines, glucides,
sucres, lipides, AG saturés, fibres) et le journal n'en fige que 4 (`kcal / protéines / glucides /
lipides`). Aucun **minéral**, **vitamine** ni **cholestérol**. On veut **enrichir** la base
d'aliments et le journal avec un **socle de micronutriments** pour aller vers un vrai suivi
nutritionnel (ex. magnésium, cholestérol).

**Non-objectif** : suivi d'objectifs / RDA (apports recommandés) par micronutriment — hors périmètre,
possible US ultérieure. Ici on **stocke, transporte et affiche** la donnée quand elle existe.

## 2. Décisions produit (validées 11/07/2026)

- **Panel « socle ciblé »** (au-delà des macros déjà stockées) — 12 champs :
  | Groupe | Nutriments (unité) |
  |---|---|
  | Lipides | **cholestérol** (mg) |
  | Minéraux | **sodium** (mg) *(+ sel dérivé = sodium × 2,5)*, **magnésium** (mg), **potassium** (mg), **calcium** (mg), **fer** (mg) |
  | Vitamines | **C** (mg), **D** (µg), **B9** / folates (µg), **B12** (µg) |
  > AG saturés et fibres restent dans leurs colonnes existantes (non déplacés).
- **Stockage = colonne JSON `micronutrients`** (map `clé → nombre`, valeurs **pour 100 g** sur
  `foods`, **valeurs figées pour la quantité** sur `food_entries`). Même patron que `portions`.
  Souplesse : ajouter un nutriment = 0 migration. Absence de valeur = **clé absente** (jamais `0`).
- **Journal = snapshot** : au moment de l'ajout, on calcule et **fige** les micros dans
  `food_entries.micronutrients` (cohérent avec la règle « l'historique n'est pas recalculé », spec 4.8 §8).

## 3. Modèle de données

### 3.1 Représentation (shared)
Type canonique, toutes clés **optionnelles**, valeurs **≥ 0**, unités fixes (mg sauf vitamines
D/B9/B12 en µg) :

```ts
// clés stables (jamais renommées) — unité encodée dans le nom
type Micronutrients = {
  cholesterol_mg?: number;
  sodium_mg?: number;
  magnesium_mg?: number;
  potassium_mg?: number;
  calcium_mg?: number;
  iron_mg?: number;
  vitamin_c_mg?: number;
  vitamin_d_ug?: number;
  vitamin_b9_ug?: number;
  vitamin_b12_ug?: number;
};
```
- `micronutrientsSchema` (Zod) : objet **strict** (clés inconnues rejetées à l'écriture app ;
  tolérance en lecture pour ne pas casser un JSON enrichi côté source), chaque champ
  `number().nonnegative().optional()`.
- Helper **`salt_mg` dérivé** (sodium × 2,5) pour l'affichage — non stocké.

### 3.2 Colonnes
- **`foods.micronutrients`** — JSON (Postgres `jsonb`, PowerSync `column.text`), défaut `{}`,
  valeurs **pour 100 g**.
- **`food_entries.micronutrients`** — JSON, défaut `{}`, valeurs **figées pour la quantité**.
- Recettes / repas types (`recipe_*`, tables 4.24) : **hors périmètre de cette US** (les micros y
  seront agrégés dans une itération suivante ; à noter dans le § différé).

### 3.3 Helpers purs (shared, `food.ts` + tests)
- `scaleMicronutrients(per100g, grams)` → mise à l'échelle (mêmes règles que `scaleNutrition`,
  clés absentes ignorées, arrondi adapté — 1 décimale pour les µg/petites valeurs).
- `sumMicronutrients(list)` → somme clé à clé sur les entrées d'un jour (pour un futur total ;
  additionne uniquement les clés présentes).
- `saltFromSodiumMg(sodium_mg)` → `sodium × 2.5`.

## 4. Sources & remplissage

| Source | Champ | Remplissage micros |
|---|---|---|
| **Bibliothèque** (`library`, 50 aliments seed) | `micronutrients` | **Enrichi manuellement d'après CIQUAL** (ANSES) — table de référence fiable pour les aliments bruts. Le seed passe les 10 clés du panel quand la donnée existe. |
| **OpenFoodFacts** (`openfoodfacts`, scan/recherche) | `micronutrients` | Mappé depuis `nutriments` (`cholesterol_100g`, `sodium_100g`, `magnesium_100g`, …) **avec normalisation d'unité** (OFF renvoie souvent des g → convertir en mg/µg). Champ souvent **absent** côté OFF (données déclaratives) → clé omise, jamais `0`. |
| **Perso** (`custom`) | `micronutrients` | Optionnel : champs repliables « valeurs détaillées » dans l'écran aliment perso (tous facultatifs). |

> ⚠️ **Disponibilité ≠ couverture.** CIQUAL = fiable et complet pour les aliments bruts ;
> OpenFoodFacts = large mais micros **majoritairement manquants**. L'UI ne doit jamais bloquer ni
> afficher `0` par défaut : **on n'affiche que les nutriments réellement renseignés**.

## 5. UI

- **Détail d'un aliment** (picker / résultat de recherche) : section repliable **« Valeurs
  détaillées »** listant les micros **présents** (libellé i18n + valeur + unité), pour 100 g et
  pour la quantité choisie.
- **Aliment perso** : bloc repliable optionnel de saisie (tous champs facultatifs).
- **Journal (jour)** : *pas de refonte des totaux dans cette US* — les totaux restent kcal + 3
  macros. (Agrégat micros du jour = **différé**, listé en §8.)
- **i18n FR + EN** : libellés des 10 nutriments + « Valeurs détaillées » + unités.

## 6. Règles & offline

- 100 % offline (comme 4.8) sauf enrichissement OFF (réseau, dégradation → micros vides).
- **Rétrocompatibilité** : `micronutrients` absent/`{}` sur les aliments et entrées existants =
  comportement inchangé. Aucune donnée détruite, aucune valeur inventée.
- Snapshot journal : figé à l'ajout ; l'édition de quantité recalcule le snapshot micros comme les macros.

## 7. Checkpoints 🔴 humains

- **Migration** `foods.micronutrients` + `food_entries.micronutrients` (ajout colonne `jsonb`
  default `'{}'`), **re-seed** des 50 aliments bibliothèque avec les micros CIQUAL, `db:types`.
  **Sync rules : rien à faire** — les streams `foods`/`food_entries` sont en `select *`
  ([powersync-sync-rules.yaml:34-37](../../technical/powersync-sync-rules.yaml)), la nouvelle
  colonne est synchronisée automatiquement.
- **Vérif device** : lecture des micros sur un aliment bibliothèque, ajout au journal (snapshot),
  import OFF avec/sans micros, offline, sync montante/descendante, FR/EN.

## 8. Différé (hors périmètre)

- **Agrégat micros du jour** + éventuel écran « détail nutritionnel » du journal.
- **Objectifs / RDA** par micronutriment (comparaison aux apports recommandés).
- **Micros dans les recettes / repas types** (agrégation `recipe_*`).
- Extension du panel (« étendu » : AG mono/poly, oméga-3, zinc, vitamines A/E/K/B1-B6…).
