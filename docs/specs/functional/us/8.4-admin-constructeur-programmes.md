# US 8.4 — Admin : constructeur de programmes éditoriaux (muscu + running)

> Composer des **programmes éditoriaux** depuis le back-office : programme → séances → (exos muscu | cibles running),
> bilingue FR+EN, **brouillon/publié**, réorganisation par glisser-déposer, archivage. Suite de l'Admin F1/F2/8.2.
> Branche : `feature/admin-8.4-constructeur-programmes` · Date : 13/07/2026.
> **⚠️ 🔴 checkpoint cloud** : migration RLS d'écriture éditoriale + `db:types` (Florian, bon projet `nsxzflxsgovriwwvflxe`).

## 0. Contexte (exploration)

- **`programs`** : `id`, `owner_id` (NULL = **éditorial**), `pillar` ('strength'|'running'), `status`
  ('draft'|'published', défaut 'draft'), `is_active` (bool — usage utilisateur, **ignoré** en éditorial),
  `level` ('beginner'|'intermediate'|'advanced', nullable), `goal` (texte nullable), `duration_weeks` (int nullable),
  timestamps, `deleted_at`.
- **`program_translations`** : `(program_id, owner_id, lang 'fr'|'en', name, summary nullable, description nullable)`,
  **une ligne par langue** (unique `(program_id, lang)`), `deleted_at`.
- **`sessions`** : `id`, `program_id`, `owner_id`, `order_index` (0-based), `name` (texte **libre nullable**),
  `session_type` (running only : 'endurance'|'fractionne'|'sortie_longue'|'recuperation', NULL en muscu),
  `target_distance_m` (int nullable, running), `target_duration_seconds` (int nullable, running), timestamps, `deleted_at`.
- **`exercise_plans`** : `id`, `session_id`, `owner_id`, `exercise_id` (FK `exercises`), `order_index`,
  `set_type` ('normal'|'warmup'|'superset'|'duration'|'bodyweight', défaut 'normal'), `target_sets` (int nullable),
  `target_reps` (texte libre nullable, ex. « 8-12 »), `target_weight_kg` (numeric nullable), `rest_seconds` (int nullable),
  timestamps, `deleted_at`. **Concerne uniquement les séances muscu** (les séances running n'ont pas d'exos).
- **RLS actuelle** (`20260706130001_programmes_rls.sql`) : `select (owner_id is null or owner_id = auth.uid())` ;
  `insert/update (owner_id = auth.uid())` → **l'admin ne peut pas écrire l'éditorial** (owner_id NULL). Fonction
  `public.is_content_editor()` (super_admin + content_editor) **déjà disponible** (US 8.2).
- **Sync rules** : `programs` du bucket `shared_content` filtre **déjà** `status='published'` ; `sessions` /
  `exercise_plans` / `program_translations` filtrent `owner_id is null and deleted_at is null` (**sans** statut). Les
  séances/exos/traductions d'un programme **brouillon** descendent techniquement mais restent **orphelins invisibles**
  (le mobile joint depuis `programs`, absent) — même pattern inoffensif que les traductions d'exercices en 8.2.
  → **Aucun changement de sync rules pour 8.4.**
- **Seed** : 1 programme muscu éditorial publié (« Fullbody débutant 8 semaines », 3 séances, 9 exos). Aucun programme
  running seedé. Le builder édite l'existant + en crée.
- **Réutilisation** : `apps/admin/src/data/exercises.ts` → `listEditorialExercises()` (picker d'exos), pattern data
  `exercises.ts`, gate `RequireContentEditor` (F2), types `@wellness/shared`
  (`ProgramLevel`, `Pillar`, `SetType`, `PROGRAM_LEVELS`, `MUSCLE_GROUPS`, `PROGRAM_SESSION_TYPES`…), `Database`.
- Admin = web, **supabase-js direct** (session admin, RLS = frontière). UUID générés client (`crypto.randomUUID()`).

## 1. Périmètre à livrer

Dans `apps/admin`, un module **Programmes** (réservé aux rôles `content_editor`/`super_admin`) — **muscu ET running** :

- **Lister** les programmes éditoriaux (`owner_id is null`, non supprimés) : nom FR, pilier, niveau, statut, date ;
  recherche par nom ; filtres pilier + statut ; tri récent → ancien.
- **Créer** un programme éditorial : **pilier** (muscu/running) — figé après création ; **niveau** (optionnel),
  **objectif** (texte libre optionnel), **durée en semaines** (optionnel) ; **nom FR + nom EN requis** ; résumé /
  description FR/EN optionnels ; **statut brouillon par défaut**.
- **Éditer les métadonnées** (mêmes champs, hors pilier) + **publier / repasser en brouillon**.
- **Composer** (écran d'édition du programme) :
  - **Séances** : ajouter, éditer (nom libre + bouton « auto A/B/C » ; running : type + distance/durée cible),
    **réordonner (glisser-déposer)**, supprimer (soft-delete + cascade exos).
  - **Séances muscu → exercices** : ajouter (picker d'exercices éditoriaux **publiés**), éditer
    (type de série, séries, reps, charge kg, repos s), **réordonner (glisser-déposer)**, supprimer.
  - **Séances running → cibles** : `session_type`, `target_distance_m`, `target_duration_seconds` (portées par la
    séance ; **pas d'exercices**).
- **Archiver** un programme (soft-delete) avec confirmation → cascade programme + traductions + séances + exos.

**Hors périmètre / différé :**
- Désarchiver / écran des archivés (idée notée dans [IDEAS.md](../../../IDEAS.md) — transverse 8.2→8.5).
- Dupliquer un programme (le repo mobile a `duplicateProgram`, hors MVP admin).
- Ajouter un exercice **utilisateur** (owner ≠ NULL) à un programme éditorial (séparation des périmètres).
- Programmes utilisateur (gérés côté mobile), filtre statut sur `sessions`/`exercise_plans` en sync (inutile, cf. §3).
- Upload média (8.3, **bloqué**), muscles secondaires, historique/audit des modifications (8.10).

## 2. Modèle de données — migration (🔴 cloud)

Migration `20260713xxxxxx_admin_editorial_programs_rls.sql` — **RLS d'écriture éditoriale** sur les 4 tables, sur le
modèle exact de 8.2 (Postgres n'a pas `create or replace policy` → **DROP puis CREATE** avec les noms d'origine
`{table}_insert` / `{table}_update` générés par `20260706130001_programmes_rls.sql`) :

```sql
-- pour chaque table T ∈ {programs, program_translations, sessions, exercise_plans} :
drop policy if exists T_insert on public.T;
create policy T_insert on public.T for insert
  with check (owner_id = auth.uid() or public.is_content_editor());

drop policy if exists T_update on public.T;
create policy T_update on public.T for update
  using (owner_id = auth.uid() or public.is_content_editor())
  with check (owner_id = auth.uid() or public.is_content_editor());
```

- **select inchangé** (`owner_id is null or owner_id = auth.uid()`) : l'admin lit déjà l'éditorial ; le mobile ne
  reçoit le publié que via les sync rules (déjà filtrées). Pas de colonne à ajouter (`status` existe déjà sur `programs`).
- **`database.types.ts`** : `is_content_editor` déjà présent (8.2) ; les 4 tables sont déjà typées. **Aucun ajout
  manuel** attendu — un `db:types` après application confirme l'alignement.
- Réutilise `public.is_content_editor()` (défini en 8.2) — **ne pas** le recréer.

## 3. Sync rules — aucun changement (🔴 pas de redéploiement)

`programs` filtre **déjà** `status='published'` dans `shared_content`. Un programme brouillon (et donc ses séances /
exos / traductions) n'apparaît pas côté mobile (parent absent → enfants orphelins invisibles). On **ne** filtre **pas**
`status` sur `sessions`/`exercise_plans` (cohérent avec les traductions d'exercices en 8.2 ; coût négligeable).
**Aucun redéploiement de sync rules pour 8.4.** Publier un programme → il descend au mobile au prochain sync.

## 4. Comportement (admin)

- **Accès** : entrée « Programmes » dans la nav admin, visible/gated pour `content_editor`/`super_admin`
  (`RequireContentEditor`, comme Exercices en 8.2).
- **Liste** (`ProgramsScreen`) : tableau (nom FR, pilier, niveau, badge statut, date), recherche nom, filtres
  pilier + statut, bouton « Nouveau programme » (choix du pilier à la création), actions éditer / publier-brouillon /
  archiver (confirmation). États loading / vide / erreur.
- **Création** : mini-formulaire (pilier requis, nom FR+EN requis, niveau/objectif/durée optionnels) → crée le
  programme **brouillon** + ses 2 traductions → redirige vers l'écran d'édition.
- **Édition** (`ProgramEditScreen`) : en-tête métadonnées éditables (nom FR/EN, résumé/description FR/EN, niveau,
  objectif, durée, statut + bouton publier/brouillon) ; **liste des séances** réordonnable (glisser-déposer) ; pour
  chaque séance, selon le pilier :
  - **muscu** : liste d'`exercise_plans` réordonnable (glisser-déposer) + ajout via **picker d'exercices publiés** ;
    édition inline des cibles (type de série, séries, reps, charge, repos).
  - **running** : champs `session_type` (select), distance (m) et durée (s) cibles, éditables sur la séance.
- **Nommage séance** : champ libre optionnel ; bouton « auto A/B/C » qui propose « Séance A/B/C… » selon l'ordre.
- **Publier** : `status='published'` (→ synchronisé au mobile). **Repasser en brouillon** : `status='draft'`
  (→ retiré de la synchro éditoriale). Publication **bloquée** si nom FR ou EN manquant (le mobile attend les deux).
- **Archiver** : confirmation → soft-delete `deleted_at=now()` du programme **et** cascade (traductions, séances,
  exos). Réutilise la logique de cascade du repo mobile (`removeSession`/soft-delete).
- **Réorganisation (glisser-déposer)** : via **@dnd-kit** (nouvelle dépendance web `apps/admin`, ~25 Ko, aucun impact
  quota build). Un drop recalcule les `order_index` contigus (0..n) de la liste concernée et persiste (update).
  Accessibilité : @dnd-kit fournit le clavier ; garder un ordre stable si le drop échoue (rollback UI + message).

## 5. Architecture (code, `apps/admin`)

- **`src/data/programs.ts`** : couche data supabase-js typée `Database` —
  `listEditorialPrograms()` (join nom FR/EN, éditorial, non supprimé, tri récent) ;
  `getProgram(id)` (programme + 2 trads + séances triées + exos triés par séance) ;
  `createEditorialProgram(input)` (UUID client, owner_id NULL, status 'draft', + 2 traductions) ;
  `updateProgramMeta(id, input)` (niveau/objectif/durée + upsert 2 traductions) ;
  `setStatus(id, 'draft'|'published')` (`.is('owner_id', null)`) ;
  `archiveProgram(id)` (soft-delete cascade) ;
  `addSession(programId, input?)` / `updateSession(id, input)` / `removeSession(id)` (cascade exos) /
  `reorderSessions(programId, orderedIds)` ;
  `addExercisePlan(sessionId, input)` / `updateExercisePlan(id, input)` / `removeExercisePlan(id)` /
  `reorderExercisePlans(sessionId, orderedIds)`. Toutes les écritures éditoriales posent **owner_id NULL** et scopent
  les lectures/écritures éditoriales par `.is('owner_id', null)`. Erreurs surfacées (retour typé, message FR).
- **`src/screens/ProgramsScreen.tsx`** (liste) + **`src/screens/ProgramEditScreen.tsx`** (édition/composition).
- **`src/components/`** : `SessionList` (séances réordonnables), `ExercisePlanList` (exos réordonnables),
  `ExercisePicker` (sélection d'un exercice publié via `listEditorialExercises()` filtré publié), et un petit
  wrapper `SortableList` (@dnd-kit) réutilisable pour les deux listes.
- **Routing** (`App.tsx`) sous `RequireContentEditor` + `AdminLayout` : `/programs` (liste), `/programs/new`,
  `/programs/:id` (édition). **AdminLayout** : rendre l'entrée « Programmes » **cliquable** (NavLink) pour un éditeur
  de contenu (garder les autres en « bientôt »).
- **i18n** `fr.ts` : `programs.*` (liste, colonnes, formulaires, piliers, niveaux, statuts, séances, types de série,
  types de séance running, actions, erreurs, confirmations, libellés distance/durée).
- **Dépendance** : ajouter `@dnd-kit/core` (+ `@dnd-kit/sortable`, `@dnd-kit/utilities`) à `apps/admin/package.json`
  (versions compatibles React 19). **Migration** RLS (§2). **Pas de sync rules, pas de code mobile.**

## 6. Sécurité
- RLS = frontière : seul un **éditeur de contenu** (F2) écrit l'éditorial (`is_content_editor()`) ; un user non-admin
  ne voit que le publié + le sien. Clé **anon** seule ; `service_role` interdit côté client. Soft-delete uniquement.
- Un programme brouillon (et ses enfants) n'est jamais exploitable au mobile (parent filtré au niveau sync).
- Picker limité aux exercices **publiés** → évite d'ajouter un exo brouillon (non synchronisé) qui créerait une
  référence orpheline côté mobile.
