# US 8.6 — Admin : import d'aliments par CSV (CIQUAL)

_Spec fonctionnelle. Statut : validée (brainstorming du 13/07/2026, Florian). Branche :
`feature/8.6-import-csv-ciqual` (depuis `dev`)._

## 1. Contexte & objectif

La base d'aliments éditoriale (`foods`, `owner_id IS NULL`, `source = 'library'`) ne contient
qu'un **seed d'une cinquantaine d'aliments**. Avant la bêta, il faut pouvoir la **remplir en masse**
depuis un CSV formaté (préparé à partir de CIQUAL + traductions EN — arbitrage G bilingue).

**Objectif** : un écran d'administration qui importe un **CSV au format défini par nous**, avec
**aperçu + validation avant écriture**, **upsert idempotent** (ré-import sans doublon), et
**rapport** de fin. Contenu **éditorial** uniquement (`owner_id NULL`, `source 'library'`).

## 2. Périmètre

- **Inclus** : écran admin d'import CSV (parse + validation par ligne + aperçu + confirmation +
  upsert `foods` & `food_translations` FR/EN + micros + rapport). Migration `foods.import_key`.
  Logique pure de validation/mapping dans `@wellness/shared` (testée).
- **Exclu** : 8.5 (CRUD/édition unitaire d'un aliment), `portions` (défaut `[]`), modération
  (8.7), rollback/annulation d'un import, import via l'app mobile. Pas de dimension visuelle
  spécifique → **maquette écartée** (écran de formulaire admin, validé à l'usage par Florian).

## 3. Contrat CSV (format défini par nous)

- **Encodage** UTF-8, séparateur `,`, **première ligne = en-têtes**, décimales avec `.`.
- **Colonnes requises** :
  - `import_key` — clé stable unique (ex. code CIQUAL). Sert à l'upsert idempotent.
  - `name_fr`, `name_en` — noms (non vides).
  - `category` — parmi `meat, fish, starchy, vegetables, fruits, dairy, nuts, drinks, other`.
  - `kcal_per_100g` — nombre ≥ 0.
- **Colonnes macros (optionnelles, nombre ≥ 0)** : `protein_per_100g`, `carbs_per_100g`,
  `sugars_per_100g`, `fat_per_100g`, `saturated_fat_per_100g`, `fiber_per_100g`.
- **Colonnes micros (optionnelles, nombre ≥ 0)** — noms = `MICRONUTRIENT_KEYS` de `food.ts`,
  unités fixes : `cholesterol_mg`, `sodium_mg`, `magnesium_mg`, `potassium_mg`, `calcium_mg`,
  `iron_mg`, `vitamin_c_mg`, `vitamin_d_ug`, `vitamin_b9_ug`, `vitamin_b12_ug`.
  → assemblées dans la colonne JSON `foods.micronutrients` (uniquement les clés fournies).
- Cellule vide sur une colonne optionnelle = valeur absente (macro `null` / micro non renseigné).
- Colonnes inconnues : **ignorées** (tolérance), signalées en avertissement non bloquant.
- Un **modèle CSV téléchargeable** (en-têtes + 1 ligne d'exemple) est fourni depuis l'écran.

## 4. Migration (checkpoint 🔴)

- Ajouter `foods.import_key text` (nullable — le contenu OFF/custom n'en a pas).
- **Index unique simple** `create unique index foods_import_key_key on public.foods (import_key);`
  → les NULL (OFF/custom) restent illimités, seules les clés non nulles (éditorial importé) sont
  uniques. Index **non partiel** volontairement : `on conflict (import_key)` de l'upsert supabase-js
  ne peut pas cibler un index partiel (pas d'arbitre). Suffisant car seul l'import écrit `import_key`.
- RLS inchangée (écriture éditoriale déjà ouverte aux éditeurs de contenu). `database.types` régénéré.

## 5. Logique partagée — `@wellness/shared/food-csv.ts` (pure, testée)

- `parseFoodCsv(rows: Record<string,string>[]): { valid: FoodImportRecord[]; errors: RowError[] }`
  où `rows` sont déjà tokenisées (papaparse côté admin).
- `FoodImportRecord` : `{ importKey, nameFr, nameEn, category, kcalPer100g, protein…?, micronutrients }`.
- `RowError` : `{ rowIndex, field, reason }`.
- Règles : champs requis présents/non vides ; `category` ∈ enum ; nombres parsables et ≥ 0 ;
  **`import_key` unique dans le fichier** (doublon intra-fichier = erreur sur les lignes en conflit) ;
  micros validés via `micronutrientsSchema`. Réutilise `MICRONUTRIENT_KEYS` / enums existants.

## 6. Flux d'import (écran admin)

1. **Upload** d'un `.csv` → **papaparse** (texte → objets lignes ; en-têtes ; champs quotés).
2. `parseFoodCsv` → `{ valid, errors }`.
3. **Aperçu** : « N lignes valides · M en erreur » + table des erreurs (ligne, champ, raison) +
   aperçu des premières lignes valides. Bouton **Importer** actif s'il y a ≥ 1 ligne valide.
4. **Confirmation** → **upsert** :
   - `foods` : upsert `onConflict = import_key` (parmi l'éditorial), `owner_id = NULL`,
     `source = 'library'`, macros/micros mappés. Récupère les `id`.
   - `food_translations` : upsert `onConflict = (food_id, lang)` pour `fr` et `en`.
   - UUID générés client pour les nouvelles lignes.
5. **Rapport** : créés / mis à jour / ignorés (avec raisons). Les lignes en erreur ne sont pas écrites.

## 7. Admin (web)

- Nouvelle entrée de nav **« Aliments »** → écran **Import CSV** (`screens/FoodImportScreen.tsx`),
  route dans `App.tsx`, gated **`content_editor` / `super_admin`** (RLS = frontière ; nav masquée
  sinon, comme exercices/programmes).
- Couche data **`data/foods.ts`** (supabase-js) : `importFoods(records): Promise<ImportResult>`.
- i18n : libellés dans `apps/admin/src/i18n/fr.ts` (admin FR uniquement — l'app mobile est bilingue,
  pas le back-office).
- Dépendance : **papaparse** (+ types) ajoutée à `apps/admin`.

## 8. Erreurs & cas limites

- Fichier vide / sans en-têtes requis → message global, rien à importer.
- Ligne : champ requis manquant, `category` inconnue, nombre invalide/négatif, `import_key` vide
  ou dupliqué dans le fichier → ligne rejetée, raison affichée.
- `name_en` manquant : **erreur** (bilingue obligatoire). (Alternative repli FR→EN écartée.)
- Échec réseau/DB à l'upsert → rapport d'échec, invite à réessayer (l'upsert idempotent rend le
  ré-essai sûr).

## 9. Tests

- **Shared (Vitest)** `food-csv.test.ts` : lignes valides → records ; chaque règle d'erreur ;
  dédup intra-fichier ; micros (clés/units) ; colonnes optionnelles vides ; colonnes inconnues
  ignorées ; mapping vers la forme d'upsert.
- **Admin** : `npm run typecheck` + `build` verts. (I/O Supabase non testé unitairement — RLS + upsert
  vérifiés à la recette.)

## 10. Definition of Done

- Import d'un CSV conforme → aperçu, confirmation, upsert idempotent (ré-import = 0 doublon),
  rapport. Micros + FR/EN peuplés. Gated par rôle.
- typecheck / lint / tests verts ; parité (admin FR).
- **Reste checkpoint 🔴 Florian** : appliquer la migration `import_key` + `db:types` + recette
  (import réel d'un échantillon CIQUAL, vérif base + affichage mobile).
