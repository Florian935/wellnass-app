## 1. Périmètre à livrer

Un **mode édition** du dashboard permettant de **réorganiser**, **masquer/afficher** et **redimensionner** les
widgets, la disposition étant **persistée** (locale + synchronisée cloud). **100 % client, aucune migration.**

**Hors périmètre / différé :**
- Ajout/suppression de widgets custom, widgets tiers, multi-« pages » de dashboard.
- Réglages par widget au-delà de visible/ordre/taille.
- Personnalisation d'autres écrans que l'accueil.

## 2. Modèle de configuration

- **Registre de widgets** (nouveau `packages/shared/src/dashboard.ts`, pur + testé) :
  ```ts
  export const DASHBOARD_WIDGET_IDS = [
    'today-session', 'nutrition-summary', 'streak', 'weight',
    'record-recent', 'muscle-volume', 'running-week',
  ] as const;
  export type DashboardWidgetId = typeof DASHBOARD_WIDGET_IDS[number];
  // Gardes piliers (widget masqué si AUCUN de ses piliers n'est actif ; 'always' = transverse) :
  export const WIDGET_PILLARS: Record<DashboardWidgetId, Pillar[] | 'always'> = { ... };
  export type WidgetSize = 'full' | 'compact';
  export interface WidgetLayoutEntry { id: DashboardWidgetId; visible: boolean; order: number; size: WidgetSize; }
  export interface DashboardLayout { widgets: WidgetLayoutEntry[]; }
  ```
- **Layout par défaut** : ordre actuel du dashboard, tous `visible: true`, `size: 'full'`.
- **Résolution (pure, testable)** `resolveDashboardLayout(stored, activePillars)` :
  1. part du `stored` s'il existe, sinon du défaut ;
  2. **fusion forward-compat** : tout `DashboardWidgetId` **absent** du `stored` (nouveau widget ajouté après
     coup) est **ajouté à la fin** avec `visible: true, size: 'full'` — jamais perdu ;
  3. **filtre piliers** : retire les widgets dont aucun pilier n'est actif — **dans les deux modes**
     (vue **et** édition) ; un widget d'un pilier désactivé n'apparaît nulle part (donc non réaffichable
     tant que le pilier reste inactif — voulu) ; un widget `always` (transverse, ex. Streak) n'est jamais
     filtré par ce critère ;
  4. **ignore les IDs inconnus** (widget supprimé du code) sans planter ;
  5. retourne la liste **triée par `order`**, `{ id, visible, size }`.
- **Masquabilité uniforme (tranché)** : **tous** les widgets sont masquables/réordonnables/redimensionnables de
  la même façon, **y compris les widgets `always`** (le flag `always` ne concerne QUE le filtrage par pilier, pas
  la masquabilité). Un Streak masqué reste listé en mode édition (non filtré par pilier) → toujours réaffichable.
  Pas de bouton œil conditionnel. Un dashboard entièrement masqué est un choix utilisateur valide (tout se
  réaffiche depuis le mode édition).
- **Écriture** : `updateSettings({ dashboardLayout })` (offline-first, synchronisé). Le stockage est le **JSON
  complet** des 7 entrées (ordre + visible + size), pas seulement les diffs.

## 3. Comportement — mode édition

- **Entrée** : bouton/action « Personnaliser » (icône ou entête du dashboard). En mode édition :
  - les cartes affichent une **poignée de déplacement**, un **bouton œil** (masquer/afficher) et une **bascule
    de taille** (compacte ↔ normale) ;
  - un léger repère visuel indique l'état « édition » (ex. bord/ًfond, ou animation discrète — la maquette tranche) ;
  - un bouton **« Terminé »** sort du mode édition.
- **Réorganisation (7.2)** : glisser une carte pour changer son `order`. Pendant le drag, le `ScrollView` ne doit
  pas défiler involontairement (activer le scroll auto près des bords en option — sinon MVP sans auto-scroll).
- **Masquer/afficher (7.3)** : l'œil bascule `visible`. Un widget masqué **disparaît de la vue normale** mais
  **reste listé en mode édition** (grisé/marqué masqué) pour pouvoir le réafficher. Le bouton œil est présent
  sur **tous** les widgets, y compris le Streak (cf. §2, masquabilité uniforme).
- **Widgets de piliers inactifs** : **absents du mode édition aussi** (pas seulement de la vue) — on ne peut pas
  réorganiser/afficher un widget dont le pilier est désactivé ; il réapparaîtra si le pilier est réactivé.
- **Taille (7.11)** : bascule `size` entre `full` (carte normale) et `compact` (**version ligne** condensée). Chaque
  widget fournit un **rendu compact** (voir §4). Défaut `full`.
- **Persistance (7.12)** : chaque changement (ordre/visible/taille) est **écrit** via `updateSettings` (débounce
  léger acceptable pour le drag) → persistant localement **et** synchronisé cloud (colonne existante).
- **Hors édition** : le dashboard rend les widgets **visibles**, dans l'ordre, à leur taille, filtrés par piliers.

## 4. Rendu compact des widgets (7.11)

Chaque widget des 7 doit exposer une **variante compacte** (une ligne : titre + valeur clé), en plus de sa carte
normale. Principe : la carte reçoit une prop `size` (ou deux composants). Contenu compact proposé :
- Séance du jour → nom séance + CTA icône ; Nutrition → kcal restantes ; Streak → « N j » ; Poids → dernière pesée ;
- Record récent → libellé record court ; Volume muscu → total kg semaine ; Running semaine → distance + séances.
La maquette fixe le gabarit compact commun. (C'est la partie la plus volumineuse du lot.)

## 5. Architecture

- **`packages/shared/src/dashboard.ts`** : registre + types + `defaultDashboardLayout()` + `resolveDashboardLayout()`
  (+ helpers de réordonnancement purs : `moveWidget(layout, id, toIndex)`), **testés** (Vitest).
- **Persistance** : réutilise `settings-repository` (`useSettings` + `updateSettings({ dashboardLayout })`) ; parse
  tolérant du JSON (fallback défaut si corrompu/absent).
- **`(tabs)/index.tsx`** : rend la liste **résolue** ; map `id → composant` ; passe `size` à chaque widget ; gère
  l'état « édition » + le conteneur drag & drop (reanimated + gesture-handler).
- **Composants** : `DashboardEditControls` (poignée/œil/taille) ; conteneur sortable ; adaptation `size` de chaque
  widget (`components/dashboard/*`).
- **i18n** : `home.customize.*` (bouton, terminé, masquer/afficher, taille, a11y) FR/EN à parité.
- **Aucune** migration / sync rule / dépendance native. **Testable USB** (JS pur).
