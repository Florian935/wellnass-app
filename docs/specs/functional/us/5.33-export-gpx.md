# US 5.33 — Export GPX d'une course

> Permet d'**exporter la trace GPS d'une course terminée au format `.gpx` standard**, partageable via
> la feuille de partage du système (autres apps : Strava, Garmin, e-mail, Drive…). Clôt le running R4.
> Branche : `feature/5.33-export-gpx` · Date : 12/07/2026 · **Statut : à valider (pas de code avant validation).**

## 0. Contexte

- Une course terminée est consultée sur l'écran **résumé/détail** [run/summary.tsx](../../../apps/mobile/src/app/run/summary.tsx)
  (`useRun(runId)` → `RunDetail`), qui affiche déjà la carte du tracé (`RouteMap`) quand `gpsTrack` existe.
- `RunDetail` expose : `startedAt` (ISO UTC), `finishedAt`, `distanceM`, `durationSeconds`, `source`
  (`gps`/`manual`), `status`, et **`gpsTrack`** (trace encodée, à décoder via `decodeTrack` → `GpsPoint[]`).
- `GpsPoint = { lat, lng, t }` où `t` = **secondes depuis le départ** (pas d'altitude captée — cf. dénivelé
  5.32 différé).
- Les modules natifs `expo-sharing` et `expo-file-system` **ne sont pas installés** → à ajouter (nouveau
  **build** requis pour la recette device).

## 1. Périmètre à livrer

Sur l'écran résumé/détail d'une course **GPS terminée avec trace non vide**, un bouton **« Exporter (GPX) »**
génère un fichier `.gpx` conforme et ouvre la **feuille de partage** du système pour l'envoyer où l'utilisateur
veut. **100 % local/hors-ligne**, aucune migration, aucun cloud.

**Hors périmètre / différé :**
- **Dénivelé / altitude** dans le GPX (`<ele>`) — différé (5.32 : aucune altitude captée aujourd'hui).
- Export **de masse** (plusieurs courses d'un coup), export **CSV/TCX**, partage direct vers une API tierce.
- Import de fichiers GPX.
- Export d'une course **manuelle** (sans trace) ou d'une course **active/non terminée**.

## 2. Comportement attendu

- **Visibilité du bouton** : affiché **uniquement** si `status === 'completed'`, `source !== 'manual'`, et
  `gpsTrack` non vide **et** décodable en **≥ 2 points valides**. Sinon le bouton est **masqué** (une course
  manuelle ou sans trace n'a rien à exporter).
- **Action** : au tap → génère le contenu GPX → écrit un fichier temporaire dans le cache app →
  ouvre la feuille de partage (`Sharing.shareAsync`) avec ce fichier (type `application/gpx+xml`).
- **Nom de fichier** : lisible et daté, ex. `course-2026-07-12-1927.gpx` (date/heure **locale** de départ ;
  pas d'espaces ni de caractères spéciaux).
- **Contenu GPX** (voir §3) : un `<trk>` avec un `<trkseg>` contenant un `<trkpt lat lon>` par point, chacun
  avec un `<time>` **absolu** (UTC ISO 8601) = `startedAt + t secondes`. Métadonnées : nom + heure de départ.
- **États d'erreur** :
  - partage indisponible sur l'appareil (`Sharing.isAvailableAsync() === false`) → message clair
    (« Le partage n'est pas disponible sur cet appareil »), pas de crash ;
  - échec d'écriture/partage → message d'erreur générique, l'utilisateur reste sur l'écran.
- **Annulation** : si l'utilisateur ferme la feuille de partage sans choisir, aucun effet (pas d'erreur).

## 3. Format GPX (règles)

- **GPX 1.1** (`<gpx version="1.1" creator="Wellness App" xmlns="http://www.topografix.com/GPX/1/1">`).
- `<metadata><name>…</name><time>…</time></metadata>` : **libellé daté généré** (voir ci-dessous) et
  heure de départ (UTC ISO). ⚠️ **Une course libre n'a AUCUN nom** (`RunDetail`/table `runs` sans colonne
  `name`) → le `<name>` est **toujours** un libellé construit côté appelant à partir de `startedAt`, p. ex.
  i18n `running.export.defaultName` = « Course du {{date}} » (date/heure **locale**). Aucune référence à un
  « nom de la course » existant.
- Un seul `<trk>` → un seul `<trkseg>` → N `<trkpt lat="…" lon="…"><time>…</time></trkpt>`.
- **Coordonnées** : `lat`/`lon` en degrés décimaux WGS84, telles quelles (aucune conversion d'unité — le GPX
  est toujours métrique/WGS84, **indépendant** du réglage métrique/impérial de l'app).
- **Temps** : chaque `<trkpt>` porte `<time>` = instant absolu ISO 8601 UTC dérivé de `startedAt` (ms) + `t`.
- **Pas de `<ele>`** (altitude non disponible — différé).
- **Points invalides écartés** : sécurité pour d'**anciennes** courses enregistrées avant le fix d'ingestion
  (null island `(0,0)`, coords hors bornes) — non émis dans le GPX.
- **Échappement XML** : le nom (métadonnée) doit être échappé (`& < > " '`) — pas d'injection de contenu.
- **Trace vide après filtrage** (< 2 points valides) → le bouton n'aurait pas dû s'afficher ; par sécurité,
  `buildGpx` renvoie `null` et l'appelant affiche l'état « rien à exporter » (défensif).

## 4. Architecture

- **Logique pure testable** (`@wellness/shared`) : **`buildGpx(points, opts)`** où
  `opts = { startedAtMs: number, name: string }` → **chaîne GPX** (ou `null` si < 2 points valides après
  filtrage). `name` est le **libellé daté déjà construit par l'appelant** (i18n, cf. §3) — `buildGpx` ne
  connaît ni la locale ni i18n. Pure, déterministe, sans dépendance native ni I/O.
- **Helper de validité coord partagé** : extraire **`isValidCoord(lat, lng): boolean`** dans
  `@wellness/shared` (rejet null island `(0,0)` + hors bornes) ; faire **`isValidFix` l'appeler** (au lieu de
  dupliquer la logique) et **`buildGpx` l'utiliser** pour filtrer les points. Évite le couplage accidentel
  avec le paramètre `accuracy` de `isValidFix` (absent sur un `GpsPoint`).
- **Helper de nom de fichier** : `gpxFileName(startedAt)` → `course-AAAA-MM-JJ-HHmm.gpx` (pur, testé).
  Prend un `Date` **ou** la string ISO UTC et extrait l'heure **LOCALE** (`getHours()`/`getMinutes()`,
  **non** UTC) — cohérent avec le libellé daté du `<name>`. (Le `<time>` des `<trkpt>` reste, lui, en **UTC**.)
- **Couche app (mobile)** : petit module `lib/gpx-export.ts` (ou fonction dans le repo running) qui :
  1. décode `gpsTrack` (`decodeTrack`) ; 2. construit le libellé i18n + appelle `buildGpx` (gère le `null`
  défensif → état « rien à exporter ») ; 3. écrit le fichier dans le cache app ; 4. vérifie
  `Sharing.isAvailableAsync()` ; 5. `Sharing.shareAsync(uri, { mimeType: 'application/gpx+xml', dialogTitle })`.
  Gère les erreurs (try/catch → message i18n). Thin, non testé unitairement (vérifié en revue + device).
  - **API `expo-file-system` (SDK 57)** : trancher dans le plan entre l'API **legacy** (`writeAsStringAsync` +
    `cacheDirectory`, plus éprouvée sur l'existant) et la **nouvelle API `File`** — préférer la legacy sauf
    raison contraire (stabilité, cohérence avec op-sqlite/PowerSync).
  - **Nettoyage cache** : réutiliser un **nom de fichier fixe** (écrasement à chaque export) plutôt que
    d'accumuler des fichiers dans le cache — le nom « lisible/daté » sert de `dialogTitle`/suggestion, pas
    forcément de nom de fichier physique. À arbitrer dans le plan (nom physique fixe vs daté + purge).
- **UI** : un bouton dans [run/summary.tsx](../../../apps/mobile/src/app/run/summary.tsx) (sous la carte ou dans
  l'en-tête d'actions), visible selon les conditions §2. État de chargement pendant la génération/partage.
- **Dépendances** : `expo install expo-sharing expo-file-system` (versions alignées SDK 57).

## 5. Offline, i18n, unités

- **Offline-first** : lecture locale + fichier local + partage OS. **Aucun réseau, aucune migration, aucun
  schéma, aucun cloud.** Fonctionne en mode avion.
- **i18n FR/EN** : libellé bouton (`running.export.cta`), titre de la feuille de partage, messages d'erreur
  (partage indisponible, échec). Nom par défaut de la course bilingue. Aucune chaîne en dur.
- **Unités** : le GPX est **toujours** en WGS84 + mètres + UTC — **non** affecté par le réglage métrique/impérial.
