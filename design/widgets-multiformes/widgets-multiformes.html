Des widgets en 3 formes, sur 3 hubs

Chaque module se pose en petit carré (½ largeur, 2 côte à côte), rectangle (pleine largeur) ou grand carré (pleine largeur). L'utilisateur réordonne, redimensionne et masque les widgets — indépendamment sur l'accueil, la muscu et la course. En muscu/course, la carte d'action reste épinglée en tête, hors grille. Le packing 2 colonnes découle du seul ordre.

🟦 Petit carré · small

🟪 Grand carré · large

Pleine largeur, haut. Version développée : métrique + aperçu / graphe.

Règles & décisions

  • 3 formes : small (½ largeur, ~carré), wide (pleine largeur, bas), large (pleine largeur, ~carré haut). Chaque widget adapte son contenu à sa forme.
  • Packing déterministe dérivé de l'ordre : deux small consécutifs → même ligne ; wide/large → nouvelle ligne pleine largeur ; small isolé → colonne gauche seule.
  • Édition = 1 colonne, drag linéaire (réutilise SortableDashboard) ; sélecteur de forme à 3 états (cycle) ; œil pour masquer.
  • Carte d'action muscu/course épinglée hors grille : non masquable, non redimensionnable.
  • 3 dispositions indépendantes stockées dans user_settings.dashboard_layout au format { screens:{ home, strength, running } } — sans migration SQL, parseur rétro-compatible (ancien { widgets:[…] } → home, full→wide / compact→small).
  • Filtrage piliers conservé : un widget dont aucun pilier n'est actif est masqué (course masquée si running off).
  • À trancher sur cette maquette : formes par défaut muscu/course (mix proposé ci-dessus) ; opportunité d'une forme large avec graphe pour Progression/Volume.
