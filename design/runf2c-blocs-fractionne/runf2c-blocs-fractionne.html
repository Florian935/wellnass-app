3 · Édition admin — réordonnancement

Même composant SortableList (drag & drop) déjà utilisé pour les exercices d'une séance muscu, réutilisé tel quel pour les blocs.

Pourquoi une seule ligne par bloc, pas 6 lignes pour « 6×400 m » : le projet a déjà exactement ce besoin côté musculation — exercise_plans.target_sets est un simple compteur sur une seule ligne (« 3 séries de 10 » = 1 ligne, jamais 3 lignes répétées). RUN-F2c reproduit ce même principe pour le fractionné plutôt que d'inventer un format différent.

Les règles qui gouvernent le modèle

R2 — Phase rapide : distance OU durée, jamais les deux Même règle que la cible globale d'une séance (hasRunningSessionTarget), appliquée par bloc.
R3 — Récupération entièrement optionnelle Un bloc sans récup (échauffement, retour au calme) est valide — les deux champs restent absents, jamais une valeur à zéro.
R4 — % VMA nullable, jamais inventé Un échauffement n'a pas de cible d'allure précise — l'absence est un vrai état.
R5 — Changer de type ne supprime pas les blocs Ils redeviennent juste invisibles tant que le type reste différent de « fractionné ».
